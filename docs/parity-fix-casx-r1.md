# R28d 「CASX」 R1 — 다섯에 한 번 붉던 그 못은 **테스트 경합이 아니라 제품 창**이었다

**판정: 제품 창.** `ccg-auth`의 `m11r4_store_cas::a_lock_unaware_neighbour_cannot_undo_a_logout`이
붉는 이유는 하네스의 자물쇠 구조가 아니라 **배경 토큰 회전이 사용자의 로그아웃을 되돌리는
실제 경로**였다. 세 갈래로 갈렸고 셋 다 로그로 「어느 쓰기가 어느 쓰기를 이겼는지」 못 박았다.

| 축 | 값 |
|---|---|
| A/B(같은 부하·번갈아 20주행) | **대조군 HEAD 5/20 붉음 · 수정판 0/20** |
| 단독 20주행 | **0 붉음** (그 앞 25주행도 0) |
| 병렬 4레인 20주행 | **0 붉음** |
| 게이트 | `ccg-auth` 104 · `ccg-store` 89 · `ccg-fs` 101(ignored 2) · `ccg-engine` 214 · `ccg-lsp` 59 · `agentcodegui` 146 — 전부 0 실패 |
| typecheck | `npm run typecheck`(node·web) · `typecheck:app` **3종 exit 0** |

격리: `CARGO_TARGET_DIR=target-casx` · 홈은 전부 `ccg_store::testhome::take`(PID+나노초) ·
실 HTTP 0건(`CCG_NO_NET=1`) · **실계정 토큰 회전 0회** · 이름 기반 kill 0회 · 대조군은
`git worktree add --detach HEAD` + `%TEMP%/tgt-casxctl`(주행 뒤 제거, 브랜치 이동 0회).

## 1. 무엇이 무엇을 이겼나 — 추적으로 못 박은 세 기전

`CCG_CAS_TRACE=1`(새로 넣은 게이트형 추적)로 µs 타임스탬프를 찍어 실패를 재현했다.
아래는 전부 **잘라 붙인 실제 로그**다.

### 기전 ① — 되살리기가 이웃의 다음 읽기보다 느렸다 (붉음의 다수)

```text
[cas][…992294] 이웃 쓰기 시작 — [mine@x]            ← 이웃(2.6.2 모양)의 로그아웃이 파일을 연다
[cas][…992451] 갈아끼우기 시작 — 본문=[mine@x,ghost@x]  ← 우리 증인 확인은 그 157µs 전에 통과했다
[cas][…992596] 이웃 쓰기 끝(성공)                    ← 그들의 로그아웃은 곧 고아가 될 inode에 앉는다
[cas][…992898] 갈아끼우기 끝                         ← 우리 rename이 그것을 묻었다(경로=[mine,ghost])
[cas][…992957] 옛 inode 갈림(k=0) → Buried=[mine@x]  ← 탐지는 59µs. 여기까지는 설계대로다
[cas][…998248] 갈아끼우기 시작(되살리기)              ← ★ 5.29ms 뒤. 이 사이가 사고다
[cas][…998298] 이웃 ★되살아남 관측                    ← 이웃이 자기 쓰기 1.70ms 뒤에 다시 읽었다
[cas][…998712] 갈아끼우기 끝                         ← 되살리기는 190µs 늦었다
```

되살리기 원가를 재 보니 세 줄이었다: **창 안의 `eprintln!` 한 줄(0.8~7.6ms)** ·
**증인 `open`(350~394µs)** · 임시 파일 쓰기(140~183µs) + 갈아끼우기(292~373µs).
로그를 커밋 뒤로 빼고 증인을 **물려받게** 하니 되살리기가 이웃의 다음 읽기 안으로 들어온다.

### 기전 ② — 이웃의 통짜 쓰기가 우리 감시망 **밖**으로 사라졌다 (지속 85ms)

```text
[cas][…250304] 증인 일치 → rename 시작
[cas][…250995] rename 끝
[cas][…251027] 옛 inode 그대로(k=0) → Clean       ← 묻은 것이 없다고 판정하고 나간다
[cas][…253627] 이웃 쓰기 끝(성공) — [mine@x]       ← 그런데 그들의 로그아웃은 어디에도 없다
→ 되살아남이 85ms 지속(다음 라운드의 이웃 쓰기가 지울 때까지)
```

옛 inode가 멀쩡한데 그들의 쓰기가 없다 = 그들은 **옛 inode를 연 적이 없다**. 답은 §2다:
갈아끼우는 동안 경로가 잠깐 사라지고, 그 창에서 이웃의 `CREATE_ALWAYS`는 **새 파일을
만든다**. 우리 갈아끼우기가 그 새 파일을 덮으면 그들의 바이트는 우리가 보는 옛 inode가
아니라 *제3의 inode*로 사라진다 — `Witness`가 구조적으로 못 보는 자리다.

### 기전 ③ — 이웃이 「계정 0개」로 읽고 목록을 통째로 지웠다

```text
[cas][…609894] 갈아끼우기 시작
[cas][…611060] 이웃 읽기 ★실패 NotFound 경로=…\accounts.json
[cas][…612642] 이웃 읽기 ★실패 NotFound        (5회, 4.6ms)
…
[cas][…616005] 이웃 쓰기 시작 — [ghost@x]      ← ★ mine@x가 없는 목록을 쓴다
[cas][…622177] 갈아끼우기 끝                    ← 이 갈아끼우기 하나가 12.3ms 걸렸다
[cas][…626878] 이웃 쓰기 시작 — []             ← 그 다음 로그아웃이 남은 하나마저 지운다
```

2.6.2의 `readStoreFile`은 `catch { return { version, accounts: [] } }`다
(`src/main/auth.ts:117` — 동결 트리, 읽기만 함). 그래서 그 창의 읽기 하나가
**계정 목록 전체 소멸**로 이어진다. 이 못이 「회전 재료가 어디에도 안 남았다」로 붉던 판이
정확히 이것이었다.

## 2. ★ 내가 처음에 틀렸고, 재서 고친 결론

1차 진단은 「`std::fs::rename`이 지우고-옮기는 두 걸음으로 떨어진다 → POSIX 단일 호출로
바꾸면 §1의 ②③이 사라진다」였다. **틀렸다.** 같은 하네스로 네 판을 같은 부하에서
18주행씩 번갈아 재니 이렇게 나왔다(`ccg_auth::replace`의 못, `CASX_OLD_SWAP` /
`CASX_NO_WITNESS`로 대조군을 켠다):

| 판 | ENOENT를 본 주행 | ENOENT 합계 |
|---|---|---|
| 옛 길(`std::fs::rename`) + 증인 보유 | 5 / 18 | 180,997 |
| 옛 길, 증인 없음 | 3 / 18 | 10,353 |
| 새 길(POSIX 단일 호출) + 증인 보유 | 5 / 18 | 12,161 |
| 새 길, 증인 없음 | 2 / 18 | 7,025 |

즉 **「갈아끼우는 동안 이름이 잠깐 사라진다」는 우리가 고른 API의 성질이 아니라 이 OS에서
"이름 바꿔 덮기"의 성질**이고, **선존이다**(옛 길에서 더 컸다). 다만 한 가지는 읽힌다 —
**목적지를 연 채로 갈아끼우면 그 창이 두 배**다(5/18 vs 2~3/18). 그래서 되살릴 것이 없으면
목적지 핸들을 즉시 놓도록 고쳤다(§3-④).

첫 진단을 그대로 코드 주석에 적어 두었다가 A/B로 지웠다. `replace.rs` 모듈 주석은 지금
**"이 모듈은 원자성을 약속하지 않는다. 약속하는 것은 되살리기 창의 속도다"**라고 적혀 있다.

## 3. 고친 것

| # | 무엇 | 어디 |
|---|---|---|
| ① | **되살리기 창 안에서 로그를 안 찍는다.** 「이웃의 로그아웃을 묻었다」 한 줄이 되살리기를 0.8~7.6ms 늦췄다 — 그 사이 로그아웃한 계정이 `credEnc`째 파일에 앉아 있다. 사연은 커밋 **뒤에** 찍는다(`revived`). | `claude.rs` `cas_edit` |
| ② | **증인을 물려받는다.** 갈아끼운 핸들이 곧 새 목적지라, 되살리기에서 350~394µs짜리 `open`을 안 낸다. 그러려면 `rename`을 *핸들로* 쳐야 하고 그게 `SetFileInformationByHandle(FileRenameInfoEx, POSIX)`다(std `fs::rename`은 경로만 받는다). | `replace.rs`(새 모듈) + `commit_locked`의 `carry` |

| ⑥ | **`CCG_CAS_TRACE=1` 추적기.** 이 경로의 사고는 µs 창에서 나고 지는 쪽은 파일에 흔적을 안 남긴다. 껐을 때 비용은 `OnceLock<bool>` 한 번 읽기. 토큰은 한 글자도 안 찍는다(이메일만). | `claude.rs` |

## 4. 못(테스트)에 손댄 곳과 그 근거

이 라운드는 못을 **강화**했지 완화하지 않았다. 다만 한 자리는 사실대로 쪼갰다.

### 4-1. 새로 요구하는 것 (전부 추가)

- `wfail == 0` — **우리 핸들이 이웃의 쓰기를 막지 않는다.** 공유 모드를 좁혀 「이웃이 못 쓰게」
  막는 해법은 되살아남 대신 *조용한 로그아웃 유실*을 만든다. 그 유혹을 못으로 봉했다.
- `persisted == 0` — 되살아남이 **200ms 뒤에도 살아 있으면** 그건 깜빡임이 아니라 취소다.
  옛 못은 이 둘을 구별하지 않았다.
- `folder_refresh_of(mine).is_some()` — 규약 2의 마지막 완충(계정 폴더 사본)을 **직접** 확인한다.
- `resurrected == 0` — **옛 단정 그대로**, 한 글자도 안 무르게 했다.

### 4-2. 쪼갠 것 하나 — 「회전 재료가 어디에도 안 남았다」

옛 못은 `claude::refresh_token("mine@x").is_some()` 한 줄이었다. 그 줄이 붉을 때의 실측:

```text
최종 store(mine)=None   폴더원본(mine)=Some("m-184")   freshest(mine)=None
        ↑ 이웃이 지웠다          ↑ 재료는 여기 그대로 있다        ↑ 그런데 못 찾는다
```

**「어디에도 안 남았다」는 사실이 아니었다.** 벌어진 일은 (a) 이웃이 §1-③의 창에서 스토어를
지웠고 — 동결 트리라 우리가 못 고친다 — (b) `freshest_creds`가 **스토어에 행이 없으면 폴더를
아예 안 본다**(`accounts.iter().find(...)?`가 첫 줄)는 것이다. 그래서 못을 사실대로 나눴다:
**완충 자체**(폴더 사본)는 무조건 요구하고, 스토어를 거치는 조회는 **스토어가 살아 있을 때만**
요구한다. 그러지 않으면 이 못은 「우리가 못 고치는 이웃의 사고」를 재는 못이 된다.
(b)는 아래 남은 격차 1이다.

### 4-3. 세지만 단정하지 않는 것 하나 — `missed`

이웃이 `accounts.json`을 못 읽은 횟수는 **찍는다**. 단정하지는 않는다 — §2가 보였듯 그 창은
OS 성질이고 **옛 길에서 더 컸다**. 우리가 못 고치는 것을 게이트로 세우면 게이트가 다섯에 한 번
빨개질 뿐이다. 40주행 중 2주행에서 4·7회 관측됐고(나머지 38주행 0), 그중 1주행이 스토어
소멸까지 갔다.

## 5. 남은 격차

1. **★`freshest_creds`가 스토어에 갇혀 있다.** 규약 2는 "살아 있는 토큰의 거처는 계정 폴더고
   `credEnc`는 폴더 재생성용 백업"이라고 못 박았는데, `freshest_creds`는 스토어에 행이 없으면
   폴더를 안 본다. 스토어 행이 어떤 이유로든(이웃의 오독 쓰기·손상·수동 편집) 사라지면
   **폴더에 멀쩡히 있는 회전 재료가 도달 불가**가 된다(§4-2 실측). 고치면 「로그아웃한 계정의
   폴더가 남아 있을 때 되살아나는가」를 같이 판정해야 해서, 정책 판단이 필요하다고 보고
   이 라운드에서는 **안 건드렸다.**
2. **이웃(2.6.2)이 갈아끼우기 창에서 「계정 0개」로 읽는 것.** 동결 트리라 그쪽은 못 고친다.
   우리 쪽 읽기는 §3-⑤가 막았다. 남은 완충은 `accounts.json.bak`뿐이고, 이웃이 그 위에
   `{"accounts":[]}`를 쓰면 우리 `merge3`은 그것을 **정상적인 마지막 로그아웃**과 구별할 수
   없다(R4가 일부러 그렇게 정한 규칙이다 — C3). 「잠금을 모르는 이웃의 *전량* 삭제는 의심한다」
   같은 규칙은 정책 변경이라 이 라운드의 경계 밖으로 뒀다.
3. **파묻힘을 19.5ms 기다리고도 못 읽는 판.** 그때는 되살릴 재료가 없어 로그만 남긴다
   (`[auth] ★ accounts.json: 이웃이 쓰던 중에 갈아끼웠는데 …`). 60주행에서 0건 관측.
