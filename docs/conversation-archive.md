# 대화 기록

채팅 상단의 **대화 기록** 버튼을 한 번 누르면 기록을 켜고, **대화 기록중**을 다시 누르면 끈다.
사이드바 **프롬프트** 아래의 **대화 기록소**에서 저장된 모든 세션을 조회한다.
목록의 한 항목은 채팅 세션 하나이며, 열면 그 세션에 저장된 모든 요청과 답변을 시간순으로
보여준다. 여러 번의 요청, 기록 중지 후 재개, 앱 재시작은 같은 세션에 계속 누적한다.
새 채팅은 새 세션으로 저장한다. 메인 채팅, 멀티 패널, 별도 채팅 창은 같은 채팅 ID를
사용하므로 표시 위치를 옮겨도 기록 묶음은 유지된다. HTML/Markdown 내보내기는 없다.
작업 폴더와 참조 폴더의 초기 파일 보관이 끝나면 기록이 켜진다. 저장 위치를 바꾸려면
현재 켜진 기록을 먼저 중지한다. 이전 위치의 데이터는 이동하거나 삭제하지 않는다.

기본 경로는 `<앱 홈>/conversation-archive`이며, 일반 설치에서는
`%USERPROFILE%/.agentcodegui3/conversation-archive`다. `CCG_HOME` 격리를 그대로 따른다.

다른 컴퓨터에서 보려면 기록을 중지해 저장을 마친 뒤, 세션 상단의 **세션 폴더**를 연다.
`Chat`과 `View`가 함께 들어 있는 해당 세션 폴더 전체를 복사하고, 다른 컴퓨터의
**대화 기록소 → 세션 가져오기**에서 그 폴더를 선택한다. 원래 작업 폴더나 다른 세션,
전역 파일 저장소 없이 대화와 코드의 변경 전후 내용을 읽을 수 있다.
가져온 세션은 기록이 꺼진 상태로 추가되며, 같은 ID가 있어도 기존 세션을 덮어쓰지 않는다.
파일 사본의 SHA-256을 검사하고 누락·손상이 있으면 가져오기를 완료하지 않는다.
보관 형식은 암호화가 아닌 JSON과 실제 파일 바이트이며 별도의 복호화는 필요 없다.
기록소 전체를 옮길 때는 기존처럼 보관 폴더 전체를 복사하고 **저장 위치 → 위치 변경**을 쓴다.

```text
conversation-archive/
  format.json                    # 형식 이름과 버전
  chats/<chatId>/
    Chat/
      format.json                # 독립 세션 형식·버전·세션 ID
      config.json                # 기록 설정, 작업·참조 폴더
      events.jsonl               # 순서·시각·출처·작업 ID + 원문 payload
      entries.jsonl              # 원문 위치, 크기, 짧은 목록 정보
      entries.idx                # 목록 행 위치/길이, 행당 16바이트
      turns/<turnId>.json        # 모델·설정·시간·사용량·상태
      active.json                # 마지막 작업, 비정상 종료 복구 정보
      files-manifest.jsonl       # 파일 경로와 보관 버전의 추가 기록
    View/
      objects/<hash 앞 2자>/<hash> # SHA-256으로 식별한 실제 파일 바이트
      files/<hash>/<filename>    # 보관본을 확인할 때 만드는 사본
```

## 수집과 조회

- 사용자가 보낸 요청, 실제 엔진 입력, 추가 지시, 승인·질문 응답, 예약 조작.
- Claude와 Codex의 해석 전 구조화 프로토콜 입출력, stderr, 런타임 상태.
- AI 메시지, 스트리밍 조각, 도구 이름·입력·출력·오류·명령 종료 정보.
- 실행 당시 설정과 엔진이 보고한 모델, 시작/종료 시각, 대기 시간, 제공된 사용량.
- 작업·참조 폴더의 일반 파일, 무시된 파일을 포함한 생성/수정/삭제 버전.
- 도구가 명시한 파일 경로와 첨부파일. 아직 없는 외부 생성 파일은 도구 종료 시 재확인한다.

기록소는 별도 탭 없이 대화와 작업을 한 흐름으로 보여준다. 요청과 답변 사이에 파일
읽기·쓰기·수정, 명령 실행, 검색, 에이전트 작업과 실행 결과를 시간순으로 표시한다.
승인·질문·사용자 응답·실행 오류도 같은 흐름에 포함한다. 기록 시작·중지, 정상 작업 완료,
주기적인 상태 조회·재시도·모델 전환 등 내부 상태 알림은 대화 본문에 표시하지 않는다.
응답 스트리밍 조각과 같은 내용의 화면 전달 로그도 중복 표시하지 않는다.
파일 보관 오류·수집 한계 알림은 본문과 파일 변경 묶음에서 제외하고, 세션 상단의
**보관 상태**를 펼쳤을 때만 별도로 조회한다. 과거 기록과 현재 보관 오류를 확인할 수 있으며,
과거 알림의 해결 여부를 자동으로 판정하지 않는다. 상세를 닫아 두면 추가 조회하지 않는다.
원문 저장 범위는 그대로 유지한다. 도구의 시작과 완료는 각각 표시하며, 펼치면 전체
입출력을 확인할 수 있다.
자동으로 확보한 파일 원본·변경 기록은 연속 구간별로 묶어 접어 둔다. 묶음을 펼치면
원본과 변경 전후 내용을 확인할 수 있다. 첫 보관을 AI의 파일 생성 행위로 표시하지 않는다.
다른 사람이 요청부터 결과까지 따라 읽을 수 있도록 프롬프트, AI 답변, 실제 도구 작업과
파일 내용이 대화의 중심이다. 파일은 경로뿐 아니라 생성 후 바이트·수정 전후·삭제 전 사본을
보관하며, 쓰기 도구에 전달한 전체 내용과 패치도 도구 입력 원문에 남는다.
기존 형식의 세션은 처음 열거나 기록을 재개할 때 자동 변환한다. 모든 과거 파일 버전과
초기 파일 목록에 참조된 사본을 세션 안으로 복사한 뒤 새 형식을 확정한다. 원래 기록은
`.legacy/chats/<chatId>`에 보존하며, 아직 변환하지 않은 세션을 위해 기존 전역 `objects`도
유지한다. 기존 전역 `viewer` 사본은 `.legacy/viewer`로 옮겨 보존한다.
새 기록은 전역 `objects`나 `viewer`를 만들지 않는다. 변환 중 오류가 나면
기존 기록을 유지하고 오류를 표시한다. 세션 간 중복 파일도 각 세션에 따로 보관하므로
이전 방식보다 전체 저장 용량이 늘어날 수 있다.
내부 `turns/`는 실행별 모델·시간 등의 상세 정보를 유지하는 용도이며,
목록의 기록 단위를 요청 하나씩으로 나누지 않는다. 원문과 파일은
128 KiB 단위로 읽는다. 화면에서 긴 내용을 나누어 보여주어도 저장 데이터는 자르지 않는다.
세션 제목·작업 폴더·최근 모델을 전체 기록소에서 검색할 수 있다.
목록의 세션을 우클릭하면 **이름 변경**과 **삭제** 메뉴가 나온다. 키보드에서는
Shift+F10으로 메뉴를 열고 F2로 이름을 변경하거나 Delete로 삭제 확인을 연다.
변경한 이름은 `Chat/name.json`에 저장하며, 기록 재개·앱 재시작·세션 가져오기 후에도
유지한다. 원래 프롬프트와 대화 원문은 수정하지 않는다.
삭제는 세션 이름과 삭제 범위를 보여 주는 확인 창에서 확정해야 실행된다.
기록 중이면 감시와 기록을 중지한 뒤 해당 세션의 `Chat`·`View` 및 해당 세션의
구형 기록 백업을 삭제한다. 실제 작업 파일·원래 채팅·다른 보관 세션은 유지한다.
구형 형식에서 여러 세션이 공유하던 전역 파일 사본은 다른 기록을 위해 유지한다.
이미지는 요청할 때 표시하며, 다른 바이너리는 원본 사본의 위치를 열 수 있다.

대화 화면은 작성자·모델, 시각과 본문을 중심으로 표시한다. 메시지 옆의 복사 버튼은
Markdown 본문을 복사하며, 코드 아이콘을 누르면 별도로 보관 원문을 확인·복사할 수 있다.
이벤트 번호와 원문 크기는 원문/상세 조회에서 표시한다. 저장 폴더 확인과 위치 변경은
기록소 우측 상단의 **저장 위치**에서 연다.
Markdown 목록·문단·제목·인용·표·코드 블록은 공유 본문 스타일을 적용하고, 기록소에 맞춰
간격과 글자 크기를 조정한다. 번호 목록의 시작 번호를 유지하며 긴 코드는 블록 안에서
가로로 스크롤한다.

색상·강조·그림자는 앱의 공통 `--bg`, `--text-*`, `--accent`, `--surface`, `--shadow-win`
값을 사용한다. 기록 중 표시 등 기능 상태에만 공통 기능색을 적용한다. 전체 화면을
재합성하는 웹 블러는 사용하지 않는다. 이벤트 목록과 카드를 메모이제이션하고 원문 JSON은
해당 페이지가 바뀔 때만 해석해, 검색창이나 부가 메뉴 조작이 기존 본문 전체를 다시
처리하지 않도록 한다.

## 성능과 저장 실패

기록이 꺼지면 수집 경로는 payload를 복제하거나 파일을 검사하지 않는다. 활성 기록은
백그라운드 기록 스레드와 OS 파일 변경 알림을 사용한다. 종료된 기록의 스레드는 정리한다.
재시작할 때 과거 모든 채팅의 감시를 시작하지 않고, 다음 실행/조회 시 필요한 기록만 연다.
세션 목록은 작은 설정·마지막 작업 정보와 처음/마지막 인덱스 행만 읽으며 메시지 원문을
스캔하지 않는다. 목록과 대화 흐름은 60행씩 조회한다. 연속된 파일 보관은 한 행으로
묶어 보내고, 펼친 구간 안의 파일만 별도로 조회한다. 도구명·대상·시작/완료·오류는 작은
인덱스 정보로 함께 보관하므로 큰 출력 본문을 열기 전에도 작업 내용을 알 수 있다.
이 정보가 없는 이전 기록은 작은 도구 이벤트만 읽어 표시하며, 큰 원문은 펼칠 때 읽는다.
한 번에 검사하는 인덱스 수를 제한하고, 내부 로그만 있는 빈 구간은 화면을 막지 않고
자동으로 건너뛴다.

이벤트는 짧게 묶어서 추가 기록한다. 원문과 목록을 쓴 뒤 인덱스를 공개하며, 실패한 쓰기는
동일한 위치에서 재시도한다. 대기열은 바이트 기준으로 제한하고 넘치면 생산자에 압력을
걸어 무한 메모리 증가와 조용한 폐기를 피한다. 파일 바이트는 스트리밍으로 복사·해시하고
동일한 내용은 같은 보관 객체를 참조한다. 실행 종료의 파일 목록 대조도 UI 스레드에서 하지 않는다.

정상 종료는 기록 스레드와 파일 보관을 정리하고 저장을 완료한다. 강제 종료 시 이미 기록된
정상 구간을 복구하고, 끝나지 않은 작업은 중단된 기록으로 표시한다. 전원 차단·프로세스 강제
종료 때 아직 메모리에 있던 마지막 묶음까지 보장하는 동기 저장 방식은 아니다.

엔진이 전달하지 않은 정보, 읽기 권한이 없는 파일, 확보 전에 사라지는 임시 파일, 파일 변경
알림의 손실 등은 복원할 수 없으므로 오류/수집 한계를 기록한다. 셸이 작업·참조 폴더 밖에서
수행하고 경로도 보고하지 않은 파일 작업까지 시스템 전체에서 추적하는 기능은 아니다.
디렉터리 링크를 무한히 따라가지 않으며 링크 대상 경로를 기록한다. 프로세스의 전체 환경
변수나 별도 인증 저장소는 수집하지 않는다.

## 검증

```text
cargo test -p ccg-store archive:: -- --nocapture
cargo test -p ccg-store
cargo test -p ccg-engine --lib
npm run typecheck:app
npm run app:build
cargo build -p agentcodegui --features custom-protocol
node scripts/poc-conversation-archive.mjs
```

네이티브 검증은 별도 임시 앱 홈과 가짜 엔진을 사용한다. 실제 계정이나 사용자의 작업 폴더를
수정하지 않는다. 원문 보존, 큰 출력의 페이지 조회, 생성/수정/삭제·첨부 원본, 기록 중지,
복구, 저장 위치 변경과 상단 기록 전환을 확인한다. 기록소 메뉴 위치, 빈 목록,
재시작 전후의 여러 요청이 세션 하나에 함께 표시되는지와 도구·파일 조회도 확인한다.
