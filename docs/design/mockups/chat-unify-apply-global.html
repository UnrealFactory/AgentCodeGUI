왜 즉시가 아닌가. 상속으로 두면 설정 한 번에 override 없는 전 채팅의 RunIdentity 해시가 동시에 바뀌고 다음 send가 전부 재스폰이 된다 (= P1d 부활). 물질화는 그 병리를 구조적으로 죽인다. §4.2
기본은 「적용 안 함」. 카드를 무시하면 아무 일도 안 일어난다. 이게 열린문제 ⑬(b)로 사용자 승인을 받는 항목이다.
전용 일괄 채널은 없다. 판정·비용 예고·거부 사유가 채팅마다 다른데 일괄 채널은 그걸 한 응답으로 뭉갠다(D7 위반). chat:identity-set N회 + 집계 카드 1장이 답이다 — 채널 수는 32 그대로.
verdict 3종이 그대로 보인다. 즉시 적용 / 턴 끝에 적용(PendingSettle) / 거부(사유). m-logic §3.6의 판정표가 사용자 문장으로 번역된 자리다.
접힌 자리도 대상이다. 적용은 자리와 무관하다 — 정체성은 채팅에 붙어 있고 접힘은 표시 상태일 뿐이다(불변식 5). 「지금 보이는 자리만」은 그걸 일부러 좁히는 선택지다.
설정 화면의 의미가 바뀐다. 이 토글은 이제 새 채팅 기본값을 편집하는 화면이다. 같은 규칙이 출력 스타일·MCP/Skill on-off에도 그대로 적용된다(§4.2 표).
노란 카드 = 목업 주석(실제 UI 아님) 모달 위 모달 금지 — 적용 카드는 설정 본문 안에서 자란다 거부는 값을 바꾸지 않는다 — 조용한 값 보정이 가장 위험한 마이그레이션 버그다(§5.2)
