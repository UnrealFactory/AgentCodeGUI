## 0. 한 줄

**공시는 배포 경로 기준으로 정했고(리드 결정), 그 기준으로 다시 재니 약속 여섯 중 넷이
나빠져 있었다.** 숨기지 않고 그대로 갈아 끼웠다 — 설치 파일 `2.4MB → 30.9MB`,
멀티 유휴 Private `253MB → 361MB`. 나빠진 이유는 하나다: **LSPDIST가 언어 서버를 배포본에
실어서 이제 실제로 돈다.** 그 대가를 사용자에게 설명하는 노트를 한 덩이 더했다.

---

## 1. 방침 — 왜 배포 경로인가

§1.6-D가 물은 것은 「어느 경로의 수인가」다. 리드 결정: **사용자가 겪는 자리 = 배포 경로.**
벤치 경로(exe가 레포 안)는 개발자만 보는 상태이고, §1.4-b가 「벤치가 만든 상태」라고 못
박았다. 인용할 때는 `launchCwd`/경로를 함께 말한다(§1.4-b · §5 규약).

**그리고 이 미결의 전제 자체가 바뀌었다.** §1.6-D는 *"패치노트의 약속은 배포 경로에서
참"*이라고 적었는데, 그때 배포 경로에는 **LSP가 안 떴다**(그게 §1.6-A2였다).
LSPDIST R2가 node 사이드카를 실어 그 결함을 닫자 **배포 경로의 값 자체가 움직였다** —
헬퍼 3이 상주한다. 즉 이 조각은 「어느 경로냐」를 고르는 일이면서 동시에
**「그 경로의 값이 바뀌었으니 다시 재는」** 일이다.

## 2. 무엇을 어떻게 쟀나

- **트리**: `git archive HEAD`(`5ab35ce`) → `target-lspdist/pn-tree`, `node_modules`는 정션.
  워크트리에 옆 갈래(HOSTI18N R2)의 미커밋 변경이 있어 **그것이 exe에 섞이지 않게** 격리했다.
- **빌드**: `CARGO_TARGET_DIR=target-lspdist/pn-target npm run tauri:build`(서명).
  스테이징된 `node.exe`는 캐시를 넣어 뒀고 **해시로 재검증**됐다.
- **배포 모사**: 생성된 `installer.nsi`의 `File /a` 줄 **5,427개**를 그대로 복제 +
  `AgentCodeGUI3.exe`. 자리는 `%LOCALAPPDATA%\ccg-patchnotes-r1`.
  exe sha256 `730e8b2d9a262e63…`.
- **메모리·창당**: `bench/multi.mjs --repeats=3 --tag=patchnotes --port=11005`,
  `launchCwd` = 배포 모사. → `multi-tauri-3.0.0-default-patchnotes-dist.json`
- **콜드 스타트**: `bench/coldstart.mjs tauri 5 --out=coldstart-patchnotes-dist`
  (`CCG_EXE`로 같은 exe 지정).
- **분모**: 2.6.2는 **박제값**(WS 712.8 / Priv 505.3 · 설치기 165,119,775 B ·
  설치 폴더 논리 664,461,448 B = 633.7MB · **8,139 파일**). **§1.4-b로 이관된 단서(분모의
  LSP 상태 미확인)를 그대로 진다** — 분모 재측정은 이 조각의 범위 밖이다.
- **기준 파일 무접촉**: `--out`/`--tag`로 새 파일만 썼다. `boot.mjs`는 출력 경로가 고정
  (`boot-breakdown.json`)이라 **쓰지 않았다**(대신 `coldstart.mjs`를 썼다 — 패치노트가
  인용하는 눈금도 그쪽이다).

### 3.1 나빠진 넷은 **한 원인**이다
설치 파일·설치 폴더·파일 수·유휴 Private이 전부 같은 것을 가리킨다:
**언어 서버 43.5MB + 전용 Node 런타임 89.1MB = 132.6MB**가 설치기에 실렸고, 그 서버가
이제 **실제로 돈다**(유휴 Private에 **101.6MB**). 옛 약속 `253MB`는 **LSP가 안 뜨던 판의 값**이다 —
§1.6-A2가 「배포본에서 코드 인텔리전스가 안 뜬다」로 올라온 그 상태에서 잰 수다.
**즉 253MB는 「더 좋았던 과거」가 아니라 「기능이 빠져 있던 과거」다.**

> **★R2 정정(확인 크리틱 PN-C1) — 열을 잘못 읽었다.** 초판은 이 자리와 패치노트 본문에
> **「약 115MB」**를 적었는데, `361MB`는 **Private** 열이고 `115.1MB`는 같은 스냅샷의
> **WS** 열 값이다. **두 열을 한 문장에 섞었다.** 같은 `procDetail`의 Private 몫은
> **101.6MB**(run별 102.6 / 101.4 / 101.6 · 중앙값 101.6)이고, 크리틱 재측정 **101.85MB**와
> 같은 자리다. `PatchNotes.tsx`의 ko/en 두 벌과 위 표·§4 표를 **102MB**로 고쳤다.
>
> 왜 이 실수가 났는지도 적어 둔다: 이 조각의 다른 칸(창당 비용·유휴 총계)이 전부 **WS**
> 눈금이라 헬퍼 몫도 반사적으로 WS를 집었다. **패치노트의 그 문장만 Private 문장이었다.**
> 수를 옮길 때 「어느 열인가」를 값과 함께 들고 다니지 않으면 나는 종류의 착오다 —
> §1.4-b가 「인용할 때 경로를 함께 말하라」고 한 규약의 **열 판**이다.

### 3.1-b 정밀도 단서 — 창당 `19.6MB`와 파일 수 `8,139`

- **창당 비용 19.6MB는 중앙값이고 회차 산포가 있다.** 내 3회는 `21.3 / 18.1 / 19.6`
  (폭 **18.1~21.3**), 크리틱 재현은 **19.2~21.1**이다. 두 계기가 겹치는 대역이고 중앙값도
  같은 자리라 **공시값 자체는 안 틀렸지만**, 이 수는 「±2MB 안에서 흔들리는 값」으로 읽어야
  한다. 창당 비용은 두 스냅샷의 뺄셈(`+창2 − 유휴`)이라 유휴 쪽 잡음을 그대로 물려받는다.
  패치노트 본문은 그대로 둔다(크리틱도 「공시값 자체는 안 틀렸다」고 판정했다).
- **2.6.2 파일 수는 `8,139`다.** 옛 패치노트가 적던 `8,141`은 LSPDIST R1 확인 크리틱 L3이
  정정한 값이고(오차 2), 위 표의 「약속하던 값」 열은 **그 옛 문장을 그대로 인용**한 것이라
  8,141로 남긴다. 실측 열만 8,139다. (패치노트 본문에서는 §3.4대로 이 줄을 아예 뺐다.)

### 3.2 그래서 설치 폴더를 갈라 말한다
```
설치 폴더 139.4MB  =  앱 자체 6.8MB  +  코드 인텔리전스 132.6MB
                                        (언어 서버 43.5 + Node 런타임 89.1)
```
**앱 자체는 여전히 6.8MB**다(2.6.2 대비 93배). 그리고 2.6.2도 같은 서버 셋을
`app.asar.unpacked` 안에 안고 다녔고 Node 런타임은 Electron 자신이었다 —
**같은 것끼리 견준 값**이라 이 비교는 정직하다.

### 3.3 시작 시간은 왜 안 고쳤나
오늘 재니 **더 빠르다**(paint 254 / usable 329.5 vs 약속 290 / 373). 약속과 **어긋나지
않으므로**(약속이 보수적이다) 그대로 뒀다. 바꾸려면 분모(2.6.2의 336 / 422)도 같은
세션에서 다시 재야 하는데 그건 이 조각의 범위 밖이고, 짝이 안 맞는 두 수를 곱해 적는 것은
LSPDIST R2에서 이미 한 번 지적받은 실수다(§1.6-E · R2-L4).
**사이드카가 부팅을 느리게 하지 않았다는 것은 이 측정으로 확인됐다.**

### 3.4 파일 수는 노트에서 **뺐다**
`8,141 → 2개`는 원래 「크롬을 안 안고 다닌다」의 증거였다. 이제 `8,139 → 5,429`라 그
역할을 못 하고(대부분은 pyright의 typeshed 스텁 5,289개다), NSIS가 만드는 `uninstall.exe`를
세느냐로 ±1이 갈리는 값이라 **사용자에게 말할 값어치가 없다.** 설치 폴더 MB로 충분하다.

## 4. 패치노트에 무엇을 바꿨나 (ko/en 두 벌)

| 자리 | 바뀐 것 |
|---|---|
| `lead` | 「66배 작아지고 … 4분의 1」 → 「**5배** 작아지고 … **5분의 1**」 + 「코드 분석은 깔자마자 된다」 한 마디 |
| 01 용량 | 설치기·설치 폴더 수치 교체 + **앱 6.8MB / 코드 인텔리전스 132.6MB 분해** + 「2.6.2도 같은 서버를 안고 다녔다」 |
| 02 메모리 | 창당 25.1 → **19.6MB**, 505→253 → **505→361MB** + 「그 안에 코드 인텔리전스 몫 **약 102MB**가 들어 있다」(★R2 정정 — 초판은 WS 열의 115를 적었다) |
| **05 코드 분석**(신설) | TS·JS·Python은 **아무것도 더 안 깔고** 된다 · Node 유무·실행 위치와 무관 · C#·C++는 설정에서 한 번 클릭 · **그래서 설치 파일이 커졌다**를 같은 문단에서 말한다 |
| 03 안정성 · 04 속도 · 06 탐색기 | 안 건드렸다 |

`MAX_VERSIONS = 5` 규약은 안 건드렸다(덩이를 더한 게 아니라 **노트 한 줄**을 더했다 —
버전 목록은 그대로 `3.0.0`·`2.6.2`·`2.6.1`·`2.6.0`·`2.5.2` 다섯이다).
버전 상승·릴리즈는 **안 했다**(지시대로 문구/수치만).

**출처 주석도 갱신했다** — 파일 머리에 결과 파일 경로·exe sha·「시작 시간은 왜 옛 값인가」를
적어 뒀다. 다음에 이 덩이를 만지는 사람이 어느 경로의 수인지 바로 알게.

## 5. 렌더 검증 — 그리고 실렌더가 아니면 못 잡았을 버그 둘

`npm run typecheck:app` 통과 · 렌더러 빌드 통과. 그리고 **실제로 띄워서** 카드를 읽었다
(격리 홈에 `ui-prefs.json`의 `ui.lang`을 심어 ko/en 각각 · CDP 11006·11007 ·
`.pncard`의 `innerText`를 그대로 덤프).

**타입체크가 초록인데 화면이 틀린 자리가 둘 있었다** — JSX가 줄바꿈 경계의 공백을 먹는다:

| 언어 | 화면에 나온 것 | 원인 |
|---|---|---|
| ko | `아무것도 더 깔지 않아도`**`호버`**`·정의 이동…` | `</b>` 뒤 줄바꿈 |
| en | `30.9MB (5.1×)`**`and`**` the installed folder` | 〃 |

둘 다 `{' '}`로 고치고 **다시 빌드해 다시 렌더해** 확인했다:
`아무것도 더 깔지 않아도 호버` · `30.9MB (5.1×) and the installed folder` ·
`completion with nothing else to install`. 두 언어 모두 `cardFound = true`,
`undefined`/`NaN`/`object Object` **0건**.

> 이 조각의 교훈 한 줄: **패치노트는 타입이 아니라 문장이 산출물이다.** `tsc`는 붙어 버린
> 낱말을 못 본다. 화면을 띄워 읽는 것까지가 검증이다.

## 6. 남은 것 — 정직하게

- **2.6.2 분모의 LSP 상태 미확인**(§1.4-b 이관분). 위 비율은 그 딱지를 진다.
  다만 **용량 수치는 디스크 실측**이라 이 흠과 무관하다 — 패치노트가 사용자에게 말하는
  값 중 흠을 타는 것은 **유휴 메모리 한 줄**뿐이다.
- **크래시 복구 0.45초는 이 조각에서 안 쟀다.** LSPDIST가 건드리지 않은 경로라 그대로 뒀다.
  다음에 그 수를 인용할 때 같이 재는 것이 맞다.
- **설치기를 실행해서 확인하진 않았다** — 사용자 실앱이 깔려 있어 NSIS를 돌리면 그것을
  건드린다(LSPDIST R1~R3과 같은 유보). 배포 모사는 `installer.nsi`의 적재 줄을 복제해 만든다.
- **`boot.mjs`는 출력 경로가 고정이라 안 썼다.** 그 하네스에 `--out`을 다는 것은
  `bench/` 코드 수정이라 이 조각의 경계 밖이다. 패치노트가 인용하는 눈금은 `coldstart` 쪽이라
  실질 손해는 없다.
- **버전은 안 올렸다.** `3.0.0` 키는 풀버전이고 앱은 `3.0.0-beta.1`이라 카드는 「현재 버전
  노트가 없으면 최신 노트」 폴백으로 이 덩이를 연다(파일 주석의 설명 그대로 · 실렌더로 확인).

## 7. 재현

```bash
# ① HEAD 격리 트리에서 굽는다(워크트리의 남 갈래 미커밋 변경을 안 섞는다)
git archive HEAD | tar -x -C target-lspdist/pn-tree
powershell -NoProfile -Command "New-Item -ItemType Junction -Path '…\pn-tree\node_modules' -Target '…\node_modules'"
cd target-lspdist/pn-tree && CARGO_TARGET_DIR=…/pn-target npm run tauri:build

# ② 배포 모사 = installer.nsi의 `File /a` 줄 복제 + exe   (%LOCALAPPDATA%\ccg-patchnotes-r1)

# ③ 메모리·창당 (기준 파일 무접촉 — --out 필수 · 포트 11000~11010)
node bench/multi.mjs tauri --repeats=3 --tag=patchnotes --port=11005 \
     --exe="$SIM\AgentCodeGUI3.exe" --cwd="$SIM" \
     --out=multi-tauri-3.0.0-default-patchnotes-dist.json

# ④ 콜드 스타트
CCG_EXE="$SIM\AgentCodeGUI3.exe" node bench/coldstart.mjs tauri 5 --out=coldstart-patchnotes-dist

# ⑤ 카드 실렌더 — 격리 홈에 ui.lang을 심고 .pncard의 innerText를 읽는다(ko/en 각각)

```

기준 결과 파일(`multi-tauri-3.0.0-default-r28jdecr1-*.json` ·
`multi-electron-2.6.2-default-r28jdecr1.json` · `boot-breakdown.json` · LSPDIST의 `-lspdist*`)은
**하나도 안 덮었다.**
