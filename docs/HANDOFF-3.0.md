# AgentCodeGUI 3.0.0 인수인계 프롬프트

아래 블록 전체를 새 세션(또는 다른 에이전트)에 그대로 붙여넣으면 된다.

---

AgentCodeGUI를 Electron에서 Tauri + Rust 기반으로 완전히 재구축하는 3.0.0 작업을
이어받아라. 레포는 `C:\Code\AgentCodeGUI`, 작업 브랜치는 이미 만들어져 있는
`feature/3.0.0-beta`다. **main은 절대 건드리지 마라** — main의 2.6.2 Electron 앱이
비교 기준이고, `src/main`·`src/preload`·`src/renderer`·`out/`·`dist/`는 기준을 보존하기
위해 얼려둔 상태다(수정 금지).

## 목적지

빠르고 가볍고 유지보수 가능한 3.0.0. 기존 기능 전부(멀티 패널·팝아웃·추가 채팅 창·
계정 전환·한도 이어서·btw 포크·LSP 뷰어·HTML 미리보기 등)를 **화면 단위로 대조해
하나도 빠뜨리지 않고**, 블라인드 나란히 비교에서 UI가 지지 않아야 한다. 여기에
신기능 세 개가 추가로 동작해야 한다:
1. 멀티채팅 기준으로 MCP·Skill을 전용으로 볼 수 있는 방법
2. 서로 다른 클로드 세션들끼리의 소통(클로드 코드 4개가 서로 대화하며 협업하는 수준)
3. 한도 소진 시 초기화 임박순으로 노는 계정을 자동 전환해 이어가는 설정 옵션

여기에 사용자가 추가로 요구한 것:
4. **디자인 리뉴얼** — "정책 거부로 모델을 자동 전환했어요" 같은 알림/배너 계열을 더
   깔끔하게. 전체적으로 더 모던·세련되면서 사용자가 편리해지는 방향이면 적용해도 좋다
   (3.0.0은 완전 리뉴얼이다). 단, 정보 밀도를 잃는 "여백만 넓힌 깔끔함"은 안 된다.
5. **사이드바 유리(아크릴)가 특정 상황에서 갑자기 진한 회색으로 바뀌는 문제 수정.**
6. **일반 채팅 + 멀티 채팅 통합** (사용자 아이디어, 채택됨) — 일반 채팅을 없애고
   「채팅」 하나로 합친 뒤, 지금 2·3·4·5·6인 패널 개수 다이얼에 **1을 추가**한다.
   1을 누르면 기존 일반 채팅 그대로(전체 IDE 레이아웃 — 탐색기·뷰어·Git·워크바 전부),
   2부터는 멀티 그리드. 1↔N 전환에서 대화를 잃지 않고, 현재 대화는 항상 1번 자리를
   지킨다. 6→1로 내려도 나머지 대화가 삭제되면 안 된다.

7. **채팅 로직의 잔버그** (사용자 지적) — 계정을 바꾸거나, 모델이 폴백되거나, 말하는
   도중 특수한 상황이 생기면 상태가 꼬이는 경우가 많다. 3.0에서는 **로직 자체가 깔끔해야
   한다.** 아래 M-LOGIC 조각이 이걸 담당하며, 이건 기능이 아니라 **기반**이라 M3(엔진)와
   같이 가야 한다.

가장 중요한 건 멀티채팅". 단일 채팅은 어느 런타임이든 60fps·드랍 0%로 통과해 변별력이

## 반드시 알아야 할 함정 (전부 실제로 밟은 것들)

1. **사용자의 실앱이 떠 있다.** 이름 기반 프로세스 kill(`taskkill /IM`) 절대 금지 —
   자기가 스폰한 PID만 정리하라. 실행·측정은 항상 `CCG_HOME` 격리로.
2. **`cargo build --release` 단독 금지.** `custom-protocol` 피처가 꺼지면 tauri가 dev로
   간주해 devUrl을 로드한다 — 릴리즈 exe가 빈 페이지를 띄우고, dev 서버가 떠 있으면
   **벤치가 dev 서버를 재는 사고**가 난다. `npm run tauri:build`를 써라.
3. **계정 복호화**: `accounts.json`의 토큰은 Chromium OSCrypt(userData의 `Local State`에
   DPAPI로 감싼 AES 키)로 암호화돼 있다. 홈만 옮기면 앱이 "복호화하지 못했어요"로 실행을
   거부한다. `bench/fixture.mjs`가 설치본의 Local State를 복사해 해결한다. 3.0의
   `ccg-auth`도 같은 스킴을 읽어야 사용자가 재로그인 없이 넘어온다(M5 제약).
4. **측정 공정성**: tao는 프로세스 시작과 함께 16×16 보조 창을 가시 상태로 만든다 —
   크기 조건이 없으면 Tauri 첫 창이 5ms로 찍히는 거짓 승리가 난다(`bench/lib.mjs`에
   200×200 필터로 막아둠). 병렬 부하에서는 `bench/pair.mjs`(A/B/A/B 교대)로 재라.
   스트리밍 메모리는 앱 몫/엔진 몫을 PID 차집합으로 분리해서 본다.
5. **엔진 프로토콜**: `systemPrompt`는 **생략**해야 claude_code 프리셋이 산다(undefined를
   넘기면 빈 프롬프트가 주입됨). `can_use_tool` 응답의 `toolUseID`는 라이브 턴에선 없어도
   되지만 고아/지연 승인 경로에서 조용히 폐기되므로 **항상 넣는 것이 계약**이다. 무응답
   승인은 타임아웃 없이 영구 정지한다. JSONL은 `lines()`로 읽지 마라(initialize 응답
   13.5KB가 read 경계를 넘는다). **job object(`KILL_ON_JOB_CLOSE`)를 엔진 크레이트 최초
   커밋에 넣어라** — 없으면 앱이 죽을 때 337MB claude.exe와 손자가 통째로 잔존한다.
6. **픽스처 규칙**(`bench/fixture.mjs`에 구현돼 있음): 스냅샷의 `session`은 반드시 null
   (가짜 세션 id를 넣으면 resume 실패 + 폴더 전환 판정으로 스레드가 통째 초기화된다),
   모든 메시지 `animate:false`, 꼬리는 `worked`, 항목 500 미만. 부팅을 조용하게 하려면
   `whatsnew.seenVersion`을 현재 버전으로 박고 `engine-auto-update.json`을 `{"enabled":false}`로.
7. **유리 버그 조사 진행 상황**: 사이드바는 자체 배경이 없고 body의 `--panel` 틴트
   (rgba(21,21,21,.70))가 아크릴 위에 얹히는 구조라, 아크릴이 꺼지면 불투명 회색이 그대로
   드러난다. **다만 "창 비활성"만으로는 재현되지 않았다**(`docs/design/glass-shots/`의
   focused/blurred 비교 — 둘 다 벽지가 정상적으로 비친다). 다른 트리거(투명 효과 끄기·
   배터리 절약·GPU 상태·원격·다중 모니터)를 계속 찾아야 한다. CDP 스크린샷은 창 합성
   결과를 담지 못하므로 **반드시 OS 레벨 캡처**로 확인하라.

## 남은 조각

각 조각은 독립적으로 개선·판정 가능해야 한다.

- **M1 셸 마감** — 멀티 유휴 0.64 → 0.5. `docs/memory-strategy.md`의 1~4군(WebView2
  프로세스 모델 스위치·렌더러 번들/lazy 분할·CDP 편향 제거·구조). 콜드 스타트 329 → ≤211ms.
- **M2 스토리지** — chats·sessionChats·maStore·talkStore·uiPrefs·profile·apiConfig·apiUsage
  (원자 저장·지연 로드·unloaded 마커).
- **M3 Claude 엔진** — 상주 CLI·승인/질문·소프트 중단·포크·백그라운드 작업·워크플로 미러.
  **착수 전 회귀 하네스 먼저**: 백그라운드가 살아있는 상태의 interrupt, 고아 통지 재주입,
  `background_tasks_changed` REPLACE 순서. 이게 2.6.2의 실제 릴리즈 사고 2종의 자리다.
- **M4 Codex 엔진 + 엔진 버전 관리**
- **M5 계정** — 로그인/전환/채팅별 격리(CLAUDE_CONFIG_DIR)/한도 조회 + OSCrypt 승계
- **M6 파일·Git·뷰어** — fs ops·git 래퍼·HTML 미리보기 스킴·아이콘
- **M7 코드 탐색기/LSP (사용자가 중요하다고 지목)** — 색인·호버·정의 이동·자동완성이
  **잘 되면서 성능도 좋고 버그도 없어야** 한다. 이 조각도 다른 조각처럼 **수치로 판정**하라
  — "잘 되는 것 같다"는 통과 근거가 아니다.

  측정 기준을 먼저 만들어라(`bench/lsp.mjs` 같은 하네스, 2.6.2와 3.0 동일 방법으로):
  · 대형 파일 열기 → 시맨틱 토큰 첫 페인트까지 ms (디스크 캐시 적중/미적중 각각)
  · 호버 응답 p50/p95, 정의 이동 p50/p95, 자동완성 첫 후보까지 ms
  · 프로젝트 프리웜 완료까지 ms, 그동안 UI가 막히지 않는지(60fps 유지)
  · LSP 서버들의 유휴 메모리와 회수(2.6.2는 10/30분 유휴 회수 + 좀비 30분 안전망)
  · 파일이 바뀐 뒤 토큰이 다시 정확해지기까지 걸리는 시간

  2.6.2에서 이미 고생한 자리들(같은 함정을 다시 밟지 마라 — 코드와 주석에 근거가 있다):
  · **C#(Roslyn)**: 프로토콜 위반(didOpen 중복·range 없는 didChange)에 **프로세스째 죽는다.**
    `didChangeWatchedFiles`를 선언하면 폴백 워처가 꺼진다(선언 금지). 프라임은 스냅샷이라
    이후 새/수정 파일 타입은 재프라임 전까지 무색 — 변화 통지 시 재프라임하되 **3초 조용
    간격 필수**(워처 편입 전 프라임은 헛프라임). `.slnx` 재생성 시 solution/open 재통지.
    루트 선택은 "참조 프로젝트 최대" sln(단일 sln이 다른 프로젝트를 가리는 사고).
  · **Verse**: 공식 심볼 호버가 안 되면 stale 인덱스 의심(UEFN 재빌드 감지 재시작).
    verse-lsp는 타이핑 중 **어휘 스코프만** 주고 리시버 멤버를 못 준다 — 스캔 기반 로컬
    멤버 소스가 필요하다(서버 한계, 클라이언트 버그 아님).
  · **시맨틱 토큰 디스크 캐시**(프로젝트별 버킷) + 프리웜이 재실행 체감의 핵심이다.
  · UE 컴파일 DB·clangd 인덱스는 앱 홈에 둔다(프로젝트 폴더 오염 금지).

  3.0에서는 이것들이 **하드코딩된 특례의 더미가 아니라** `ccg-lsp`의 서버 스펙(ServerSpec:
  실행 명령·루트 판별·초기화 옵션·캐시 키·재프라임 정책) 한 항목으로 표현돼야 한다.
  새 언어 추가가 스펙 1개 추가로 끝나는 게 확장점 기준이다.

- **M-WF 워크플로/서브에이전트 카드에 effort 표시 (사용자 요청)** — 지금은 모델만 나온다
  (`src/renderer/src/components/Chat.tsx:4224`, `{a.model && <span className="mt">`).
  effort도 함께 보이게 하라. **단, 추측으로 만들지 마라**:
  1. 먼저 CLI 와이어에서 `system/task_progress`의 `workflow_progress` 배열 안
     `workflow_agent` 항목이 effort를 실어 보내는지 **실측으로 확인**하라
     (`src/main/claude/engine.ts:1427-1451`가 그 프레임을 읽는 자리고, `scripts/poc-rs/`가
     프레임을 `%TEMP%\ccg-poc-rs\*.jsonl`로 덤프한다 — 워크플로를 한 번 돌려 캡처하면 된다).
  2. 실려 오면 `WorkflowAgent`(protocol.ts)에 필드를 추가하고 카드에 모델 옆 칩으로 표시.
  3. **안 실려 오면 지어내지 마라.** 앱은 스크립트가 에이전트별로 지정한 effort를 알 수 없다

- **M-LOGIC 채팅/실행 상태 정리 (기반 조각 — M3와 함께 간다)**

  사용자 지적: "계정 변경하거나, 그냥 말할 때 뭔가 특수한 경우가 생기거나, 폴백돼서
  모델이 바뀌거나 할 때 꼬이는 상황이 많다." 2.6.2 코드를 짚어보면 원인이 분명하다 —
  **한 실행의 정체성(누가·어떤 모델로·어디서 도는가)이 암묵적이고 여러 곳에 흩어져 있다.**

  실제 근거:
  - `src/main/claude/engine.ts:1185` 의 `optsMatch`가 cwd·resume·model·mode·effort·
    useApi·account·systemPrompt·addDirs·outputStyle **11개 필드를 손으로 비교**한다.
    필드가 늘 때마다 여기를 고쳐야 하고, 빠뜨리면 "옵션을 바꿨는데 예전 옵션으로 계속
    도는" 조용한 버그가 된다(출력 스타일이 뒤늦게 추가된 흔적이 주석에 남아 있다).
  - picker(모델·모드·계정)는 렌더러 `useState`, 채팅 파일 저장본, 실행 시점 RunRequest로
    **세 벌** 존재한다. 어느 게 진실인지 코드에 명시돼 있지 않다.
  - 모델 폴백은 엔진이 렌더러 picker를 뒤에서 바꾼다(`App.tsx:467-473` setPicker).
    그러면 다음 턴의 `optsMatch`가 어긋나 재스폰되는데, 사용자는 그 사실을 모른 채
    말을 이어간다.
  - 계정 변경은 격리 CONFIG_DIR 물질화 + 재스폰인데, 실행 중(busy)일 때·예약 큐가
    있을 때 어느 계정으로 나가는지가 규약으로 정의돼 있지 않다.
  - 한도 자동 이어서가 같은 상태를 만지는 **또 다른 행위자**다.
  - busy 중에는 채팅 전환·새 채팅·삭제가 조용히 no-op이라(`App.tsx:774,799,811`),
    사용자는 클릭했는데 아무 일도 안 일어나는 경험을 한다.

  3.0에서 요구하는 것:
  1. **RunIdentity를 값 하나로.** {engine, account, cwd, addDirs, model, effort, mode,
     apiMode, systemPrompt, outputStyle}을 구조체 하나로 묶고 재사용 판정은 그 값의
     비교(또는 해시)로만 한다. 필드를 추가해도 비교 로직을 고칠 필요가 없어야 한다.
  2. **명시적 상태기계.** Idle → Starting → Streaming → AwaitingUser(승인/질문) →
     Interrupting → Ended 를 전이표로 코드에 박고, 각 전이에서 허용되는 명령을 정의한다.
     "이 시점에 이 명령이 오면?"이 표에서 답이 나와야 한다.
  3. **설정 변경은 명령이지 즉시 반영이 아니다.** 렌더러는 "이 채팅의 정체성을 이렇게
     바꿔줘"를 요청하고, Rust가 (a) 지금 반영 (b) 이번 턴 끝나고 반영 (c) 거부 중 하나로
     답한다. 그 결정이 **UI에 보여야** 한다. 지금처럼 렌더러가 몰래 바꾸는 경로는 금지.
  4. **예약 큐는 정체성 스냅샷을 함께 들고 간다.** 예약할 때의 계정·모델로 나간다는 게
     사용자에게도 코드에도 명확해야 한다.
  5. **폴백은 사용자에게 보이는 상태 전이.** 자동 전환됐으면 그 채팅의 정체성이 실제로
     바뀐 것으로 기록하고, 되돌리는 방법을 준다.
  6. **busy 중 사용자 조작은 침묵 no-op 금지.** 큐에 넣든, 거부하고 이유를 말하든,
     반드시 반응한다.
  7. **회귀 하네스 필수.** 상태기계를 재생(replay)으로 때려서 다음 조합을 전부 검증:
     계정 변경 중 턴 시작 / 폴백 직후 계정 변경 / busy 중 채팅 전환 / 예약 큐가 있는
     상태에서 한도 소진 → 자동 이어서 / 중단 직후 재개 / 백그라운드 작업이 살아있는
     상태의 중단. 이 조합들이 2.6.2에서 실제로 꼬인 자리다.

## 작업 방식 (반드시 지켜라)

- 조각마다 **빌더 서브에이전트 1 + 새로운 컨텍스트를 가진 가혹한 크리틱 1**. 빌더는 절대
  자기 작업을 스스로 채점하지 않는다. 크리틱은 **실제 빌드를 직접 실행**해 기존 앱과
  비교하고(가능하면 블라인드 A/B, 성능·메모리는 반드시 측정 수치로), **남은 가장 큰 격차
  하나**를 지목해 다시 빌더에게 돌려보낸다. 라운드 수는 정해져 있지 않다 — 그 조각이
  기준을 이길 때까지 돌려라.
- 서브에이전트는 전부 **Opus 5, effort max**로 스폰하라. 리드는 세션의 너 하나면 된다.
- 여러 에이전트가 동시에 돌 때는 **파일 경계를 나눠줘라**(예: 셸 담당은 `src-tauri/`·
  `crates/`·`app/src/api/`, 디자인 담당은 `docs/design/`, 벤치 담당은 `bench/`). 안 그러면
  `git add -A` 한 번에 남의 작업 중 파일이 쓸려 들어간다(실제로 한 번 발생).
- 커밋은 **조각별 경로 지정**으로. 커밋 메시지는 한국어로 상세히(무엇을·왜·무엇을 실측했나).
  푸터: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
- `progress/data.js`를 갱신해 라이브 진행 페이지를 유지하라.
