## 1. D2 — 사정거리가 진짜 늘었는가 → **그렇다**

R1의 구멍(M2)이 닫힌 것을 확인한 뒤, **못을 알고 피하려는 손**과 **정상 리팩터가 내는
사고**로 변이 열을 걸었다(`docs/critic/tools/critic-small3-r2-mutate.mjs`).

| 변이 | 무엇을 부쉈나 | `cargo test` | 하네스 | 판정 |
|---|---|---|---|---|
| M1 | `labels()`를 리터럴로 | **101** | 1 | 문다 |
| **M2** | 빌더만 리터럴로 (R1의 구멍) | **101** | 1 | **닫혔다** |
| M3 | en 한 칸 표류 | **101** | 1 | 문다 |
| E1 | 빌더 안에서 `concat!` | **101** | — | 문다(따옴표가 남는다) |
| E2 | 빌더 밖 `const`에 한국어 리터럴 | **101** | — | 문다(검사 ③) |
| **E3** | 빌더 밖 `const`에 유니코드 이스케이프 | **0 ★** | 1 | **구멍** |
| **E6** | 빌더 밖 `const`에 `concat!("첨","부할 파일 선택")` | **0 ★** | 1 | **구멍** |
| E4 | `labels()` 안에서 `ccg_fs :: t(` 공백 | **101** | — | 문다 |
| **EPAIR** | 구조분해 순서만 뒤바꿈 | **0 ★** | **0 ★** | **★구멍(중)** |
| ESRC | 동결 원문을 감춘다 | **101** | — | 조용히 안 넘어간다 |

**닫힌 것 둘을 먼저 적는다.** 지시가 의심한 두 자리는 **멀쩡했다**:

- **`::` 둘레 공백(UPDATER R2의 전례)** — `ccg_fs :: t(`로 바꾸면 `split("ccg_fs::t(")`가
  0건을 내지만, 못이 `assert_eq!(ours.len(), 4)`를 **먼저** 세우므로 빈 벡터가 조용히
  통과하지 못한다. **exit 101**로 붉어졌다.
- **동결 파일 부재 시 조용한 스킵** — `src/main/index.ts`를 감추자
  `.expect("동결된 2.6.2 원문을 못 읽었다")`가 **크게 죽는다**(exit 101). 스킵이 아니다.

## 2. 결함

### 치명 — **없다**

### 중

**R2-D1. 빌더가 값을 *올바른 자리에* 놓았는지는 아무도 안 본다(EPAIR).**

R2의 못은 *"빌더가 `labels()`가 준 값 **말고는** 아무 말도 못 하게 돼 있는가"*를 강제한다.
그 명제는 참이 됐다. 그러나 **"그 값들을 제 짝에 놓았는가"** 는 어디에도 안 걸려 있다.

구조분해 한 줄의 **순서만** 바꾸면 된다:

```rust
-    let [title, f_all, f_img, f_txt] = labels();
+    let [f_all, title, f_img, f_txt] = labels();
```

리터럴도 0, 한국어도 0, `labels()`도 그대로, 변수 이름도 그대로다. 그래서:

- `the_builder_can_only_say_what_labels_gave_it` — **통과**(①②③ 전부 만족)
- `the_labels_still_mirror_the_frozen_262_wording` — **통과**(`labels()` 무변)
- `the_dialog_labels_follow_ui_lang` — **통과**(`labels()` 무변)
- `scripts/poc-small3-dialog-i18n.mjs` — **통과**(`.set_title(title)`·`.add_filter(f_all,`이
  글자 그대로 남아 있어 이름 기반 검사도 못 잡는다)

즉 **레포의 자동 검사 전부가 초록**이다. 제품은 이렇게 된다(제품 코드를 안 건드리고
`rustc`로 독립 스니펫을 돌려 확인했다):

```
원본  : set_title=첨부할 파일 선택 | 첫필터=첨부 가능한 파일
EPAIR : set_title=첨부 가능한 파일 | 첫필터=첨부할 파일 선택
```

대화상자 **제목이 「첨부 가능한 파일」**이 되고 **첫 필터 이름이 「첨부할 파일 선택」**이
된다 — `ko`·`en` **양쪽 다** 깨지고, §3.4-B가 지키려던 "2.6.2와 같이 「첨부 가능한 파일」이
첫 줄" 규약도 깨진다. 사용자가 바로 알아보는 종류의 어긋남이다.

**왜 중인가.** 이것은 R2가 닫겠다고 선언한 **바로 그 축(호출부 배선)** 이다. 보고서 §6.2가
정적 못을 *"배선은 정적 못이 잡고"* 라고 요약했는데, 배선은 **「어떤 값을 쓰나」와
「어느 자리에 쓰나」 둘**이고 R2는 앞의 하나만 닫았다. 게다가 EPAIR은 E3/E6과 달리
**악의가 필요 없다** — 구조분해 줄을 만지는 평범한 리팩터가 그대로 내는 사고다.

**값싼 처방 둘**(어느 쪽이든 이 부류 전체가 사라진다):
1. `labels()`가 배열 대신 **이름 있는 구조체**를 돌려준다(`Labels { title, all, image, text }`).
   위치로 섞을 방법 자체가 없어진다 — 못을 늘리는 게 아니라 **버그를 표현 불가능하게** 만든다.
2. 그게 과하면, 못 ①에 구조분해 줄을 글자로 고정하는 한 줄을 더한다
   (`assert!(call.contains("let [title, f_all, f_img, f_txt] = labels();"))`). 싸지만 이름
   리팩터에 걸리는 값이라 1을 권한다.

### 낮음

**R2-D2. 「연속 한글」을 안 남기는 우회는 `cargo test`를 통과한다(E3·E6).**

검사 ②는 **빌더 구간 안의 `"`** 만 금지하고, 검사 ③은 **연속된 한국어 문구**만 찾는다.
그 사이로 빠지는 형태가 있다 — 빌더 **밖**에 상수를 두고 그 문자열을 소스에 연속
한글로 남기지 않으면 된다:

```rust
const SNEAK: &str = concat!("첨", "부할 파일 선택");   // E6
const SNEAK: &str = "\u{cca8}\u{bd80}\u{d560} …";       // E3
…
.set_title(SNEAK)   // 빌더 구간에 따옴표가 없다
```

둘 다 `cargo test` **exit 0**이고 제품은 `ui.lang=en`에서 한국어 제목을 낸다.
**다만 하네스(`poc-small3-dialog-i18n.mjs`)가 둘 다 잡는다**(exit 1 —
`set_title/add_filter 넷이 labels()의 값을 그대로 받는다`가 이름으로 대조하기 때문).
그래서 합쳐 보면 방어는 서 있고, 등급을 낮음으로 둔다.

정확히 어긋난 것은 **보고서의 문장**이다. §6.2는 검사 ③이
*"문구의 출처가 하나임을 강제한다"* 고 적는데, 실제로 강제하는 것은
**"연속된 한국어 리터럴의 출처가 하나"** 다. `concat!`·이스케이프·런타임 조립은 밖이다.
(이 부류를 진짜로 닫으려면 검사 ③을 소스 문자열 대신 **`labels()` 밖에서 `set_title`에
들어가는 값이 있는가**로 뒤집어야 하는데, 그건 사실상 R2-D1의 처방 1과 같은 이야기다.)

**R2-D3. `LANG_TTL_MS` 값 자체에는 못이 없다.**

D4의 신설 못은 `lang_pack`/`lang_unpack`의 **왕복**만 잰다. 실제로 부숴 보면:

| 부순 것 | 결과 |
|---|---|
| `lang_pack`에서 값 비트를 뺀다 | **FAILED** (`왕복이 깨졌다 at=1 en=true`) — 문다 |
| 시프트를 `<< 2`로 잘못 잡는다 | **FAILED** — 문다 |
| **`LANG_TTL_MS` 2000 → 60000** | **102/0/2 전부 통과** — 안 문다 |

TTL을 1분으로 늘려도 아무도 안 붉어진다. 사용자 체감은 "설정에서 언어를 바꿔도 1분
동안 옛 언어"인데, 이건 D4가 만든 회귀가 아니라 **R1부터 없던 못**이라 낮음이다.
(내가 격리 사본에 임시 못을 넣어 잰 결과 **현재 값의 거동은 정상**이다 — §3.)

### 결함이 아닌 것(확인만)

- **D4 단일 원자화는 진짜 동작 무변이다.** 격리 사본에 임시 못을 넣어 실제 거동을 쟀다:
  `first=한` → (2초 안에 `ui-prefs`를 `en`으로 바꿔도) `within_2s=한` →
  (2.2초 뒤) `after_2.2s=en`. **잡고 있다가 제때 푼다** = R1과 같은 의미론.
  찢어진 관측(R1의 D4)은 단일 원자라 구조적으로 사라졌다.
- **D1·D3 정정 수치 전부 재현.** `58/41` · `.mjs` 6건의 **줄 번호까지** 일치 ·
  묘비 `5+3+12=20` 정확.
- **틀린 문장을 지우지 않고 `★R2 정정` 인용구로 남긴 것**은 이 레포의 기록 규율에 맞고,
  R1 본문을 읽는 사람이 오도되지 않게 문서 머리에 "§3의 142는 R1 시점 값"이라고
  못 박아 둔 것도 정확하다.
- **커밋 경계 깨끗**: 3파일. `crates/ccg-lsp`·`tauri.conf.json`·`docs/critic/` 미접촉.
  옆 갈래(LSPDIST)가 같은 트리에서 도는 중인데 한 파일도 안 섞였다.

## 3. 남은 가장 큰 격차 (하나)

> **배선의 「짝」 축이 여전히 무방비다 — `labels()`가 배열을 돌려주는 한 EPAIR은 언제든
> 다시 난다.**

R2는 "빌더가 **무엇을** 말하는가"를 닫았다. 남은 것은 "빌더가 그것을 **어디에** 놓는가"다.
지금 구조에서 그 둘 사이를 잇는 것은 **구조분해 한 줄의 위치 대응**뿐이고, 그 줄은
어떤 못도 어떤 하네스도 안 본다. 이 라운드가 세운 방어가 촘촘할수록 **남은 한 구멍이
유일한 통로**가 되므로 값이 더 크다.

처방은 못을 하나 더 박는 것이 아니라 **표현 불가능하게 만드는 것**이다 —
`labels()`가 `[String; 4]` 대신 이름 있는 구조체를 돌려주면 `set_title(l.title)`·
`add_filter(l.all, …)`가 되고, 순서를 바꾸는 사고 자체가 컴파일 단계에서 사라진다.
못 셋(런타임·배선·2.6.2 대조)은 그대로 쓸 수 있다.

> 참고: **제품 영향이 가장 큰 미결은 여전히 §3.4-A**(호스트 `t()` 58 vs 2.6.2 238,
> 미포장 사용자 가시 문자열 60~70)이지만, 그것은 지시가 이번 범위 **밖**으로 못 박았고
> 보고서 §10이 크리틱 R1의 목록을 **정확히** 이월했다(실물 세 자리 · 값싼 순서 ·
> 기각한 후보까지). 이 라운드에 대한 격차로는 위 「짝」 축을 든다.

## 4. 재현 방법

```bash
# 1) 오염 없는 트리 (npm install 0회)
git archive 28eb7e0 | tar -x -C %TEMP%\ccg-small3-crit-r2
mklink /J %TEMP%\ccg-small3-crit-r2\node_modules C:\Code\AgentCodeGUI\node_modules
#    app/dist는 gitignore라 아카이브에 없다 → 최소 스텁 셋(index/toast/tray.html)

# 2) 기준선
set CARGO_TARGET_DIR=C:\Temp\target-small3-crit-r2
cargo test -p agentcodegui --features custom-protocol      # 144/0/1
cargo test -p ccg-fs                                       # 102/0/2
cargo build --release --features custom-protocol           # exit 0 · warning 0

# 3) 변이 열 (반드시 격리 사본에)
node docs/critic/tools/critic-small3-r2-mutate.mjs <격리트리> M1|M2|M3|E1|E2|E3|E6|E4|EPAIR|ESRC|restore

# 4) 정리: 정션을 **먼저** 끊고 지운다 (안 그러면 워크트리 node_modules가 지워진다)
rmdir %TEMP%\ccg-small3-crit-r2\node_modules
```

`docs/critic/critic-small3-r2-mutations.json`.
R1 판정문과 그 계기는 `docs/critic/small3-critic-r1.md` ·
`docs/critic/tools/critic-small3-{r1,mutate}.mjs`.
