# R28d 「WCAP」 확인 크리틱 R3 — 경계는 진짜로 맞췄다. 그 경계가 「누가 턴을 열었나」에 따라 뒤집히는 자리를 찾았다

판정 대상: `468d905` (R28d WCAP R3). 크리틱은 코드를 한 줄도 안 고쳤다 —— 전부 직접 빌드·주행·실측했다.
빌더 보고서(`docs/parity-fix-wcap-r1.md` §11~§16)와 커밋 메시지는 **근거로 쓰지 않았다**(대조 대상일 뿐).

**판정: 합격(pass=true).** R2가 실패시킨 최대 격차(`tool_result`가 턴 경계를 넘으면 엔진 71발 /
렌더러 2발)는 **진짜로 닫혔다.** 내 사본·내 탐침·내 대조군으로 71 → 2를 재현했고, 빌더가 적은
숫자는 **한 자리도 안 틀렸다**(⑦ 71→2 · ⑤ 짝 없는 결과 71→2 · 대조군 `5 passed; 2 failed` ·
계기 눈금 「재스폰 0 · CLI턴 71」 · §14.2의 47/53/71까지 전부). 체크리스트 넷도 전부 초록이다.

다만 **새로 하나 팠다**: 두 축의 공통 문장 「이 턴이 연 비어 있지 않은 도구 그룹」은 **누가 턴을
열었느냐에 따라 답이 뒤집힌다.** 엔진 스스로 연 재개 턴(`user-echo`)에서는 스토어가 그 턴의 도구를
**앞 턴 그룹에 밀어 넣기** 때문이다(§4.3). 지금은 그 표면에서 `turnDidWork`를 아무도 안 읽어
계수 궤적은 안 갈리지만, 같은 문(門)의 세 번째 판이고 화면은 이미 거짓이다.

## 2. 체크리스트 2의 인과 — 내 대조군이 원인을 특정한다

레포를 한 글자도 안 고치고 `%TEMP%` 사본에서 **R3의 그 한 조각만** R2로 되돌렸다
(`born == cur` 가드를 지우고 무조건 `mark_output()`). 빌더의 못이 아니라 **내 탐침**
(`critr3_probe.rs`)으로 잰 값이다. 12시간 · 시각 미상(배너형) · 눈금 = stdin 프롬프트 줄:

| 대본 | R2 대조군 | HEAD(R3) |
|---|---|---|
| **P12 — 앞 턴 도구의 결과만 오는 재개** | **71발 · attempts 0 · 안 접힘**(재스폰 70) | **2발 · attempts 2 · ready+auto_paused**(재스폰 1) |
| **짝 없는 도구 결과** | **71발 · attempts 0 · 안 접힘** | **2발 · attempts 2 · 접힘** |
| 빈손(순수 문전박대) | 2발 · attempts 2 · 접힘 | 동일 (불변) |
| 매 턴 새 도구(결과 없이 죽는다) | 71발 · attempts 0 · **재스폰 0** | 동일 (불변) |
| 같은 턴 도구 쌍 / 매 턴 글자 한 줄 | 71발 · attempts 0 | 동일 (불변) |
| 사이드체인 도구만 | 2발 · attempts 2 · 접힘 | 동일 (불변) |
| 두 턴에 한 번 빈손 | 47발 · attempts 1 | 동일 (불변) |

빌더의 못을 대조군에 얹으면 **`5 passed; 2 failed`**, 붉은 메시지 두 줄 다 `left: 71 right: 2`.
보고서의 문장과 글자까지 같다. **판별력 있음 · 과잉 절단 없음.**

**계기 눈금 정정도 확인했다**(크리틱 R2 §4.1): 「결과 없이 죽는 도구 호출」 판은 **재스폰 0 ·
프롬프트 71**이다. R2의 `spawns` 눈금으로는 71발이 0으로 보였다 —— 그 오독은 이번에 고쳐졌고,
그 위에 서 있던 못 ⑥의 설계 근거도 다시 세워졌다.

## 3. 체크리스트 1 — 밤샘 주행 · 헛발질 (합격)

내 탐침으로 직접 잰 값이다(가상 시계 62시간).

* **엔진 · 창이 5시간씩 넘어가고 매 턴 실제 출력** → **12발 · attempts 0 · 안 접힘.** 정지 없음.
* **엔진 · 시각 미상 축에서 매 턴 글자 한 줄**(창이 안 넘어가도 ②가 판정) → 71발 · 안 접힘.
* **엔진 · 같은 벽 · 빈손** → **2발 · attempts 2 · `ready`+`auto_paused`** — RCAP 동작 불변.
* **렌더러** → `poc-limit-resume` ②③(훅 실구동)이 같은 착지, 249/0.

**배너 문구(체크리스트 4의 뒷다리)는 사실과 맞는다.** `Chat.tsx:3364`의 「자동으로 이어서 보낸
turn이 계속 한도에 막혔어요 — 눌러서 이어가기」와 엔진 공지(`runtime.rs:3456`)는 둘 다
`attempts >= MAX_AUTO_ATTEMPTS` **한 자리에서만** 선다. 위 표에서 그 자리는 「빈손 · 같은 벽」
판뿐이고, 밤샘 주행(12발·47발·71발)에서는 한 번도 안 뜬다.

## 4. 체크리스트 2 — 같은 대본을 양쪽에 먹였다

### 4.1 렌더러 축은 **픽스처가 아니라 스토어가** 답했다

R2가 지적한 「합성 픽스처」 문제를 피하려고, 이번엔 손으로 만든 스레드를 안 썼다. `begin` /
`user-echo` / `status` / `tool-start` / `tool-end` / `assistant-stream` / `assistant-done` /
`result`를 **실제 리듀서**에 먹여 스레드를 짓고, 그 스레드를 `turnDidWork`에 넣었다.

| 대본 | 엔진(HEAD) | 렌더러(실제 스토어) | |
|---|---|---|---|
| 프레임 없음 / 추론만 / 빈 assistant / 공백 스트리밍 | 거짓(2발·접힘) | 거짓 | ✓ |
| assistant 텍스트 / 스트리밍 텍스트 | 참(71발) | 참 | ✓ |
| 같은 턴 도구 호출+결과 | 참 | 참 | ✓ |
| 결과 없이 죽는 도구 호출 | 참 | 참 | ✓ |
| **P12 — 앞 턴 도구의 결과만** | **거짓**(2발·접힘) | **거짓** | ✓ **닫혔다** |
| **짝 없는 도구 결과** | **거짓**(2발·접힘) | **거짓** | ✓ **닫혔다** |
| 사이드체인 도구(`parentToolId`) | 거짓 | 거짓(스토어가 `subagents`로 보낸다) | ✓ |

R2 §3.2 대조표의 **유일한 불일치 줄이 사라졌다.** 15줄이 전부 같은 답이다.

`poc-limit-resume.mjs`의 새 `crossTool` 픽스처
(`{kind:'toolgroup', tools:[…]}`를 사용자 말풍선 **앞**에 두는 배치)도 **스토어가 실제로 만드는
모양과 같다** —— 내 스토어 탐침이 만든 스레드가 `user TG(tg2:1) assistant! user assistant!`다.
R2 §4.3이 지적한 「불가능한 픽스처」의 재발은 **없다**.

### 4.2 궤적도 같다

R2 §3.1의 6단 대본은 그대로 `[0, 1, 0, 0, 1, 2]`로 양쪽 일치(판정 로직이 R3에서 안 바뀌었고,
`poc-limit-resume` J절이 훅 실구동으로 잠근다 · 249/0).

### 4.3 ★ 새로 판 것 — 그 경계는 **누가 턴을 열었느냐**에 매달려 있다

두 축의 공통 문장은 이제 「**이 턴이 연** 비어 있지 않은 도구 그룹」이다. 그런데 렌더러에서
「이 턴」을 정하는 것은 `openGroupId`이고, 그 값을 **비우는 자리는 `begin`·`assistant-*`·
`verdict(blocked)`·`interrupt`뿐**이다 —— `result`도, **`user-echo`도 안 비운다**
(`app/src/store/session.ts` 623·684·748·791·799·811·817행 대 629행).

엔진이 스스로 연 재개 턴은 `user-echo`다(`consume_hold` → 큐 `LimitResume` 항목 →
`hub.rs:1267`의 `user-echo`). 그래서 **텍스트 없이 도구만 여는 재개 턴**에서 스토어는 그 도구를
**앞 턴의 열린 그룹에 밀어 넣는다.** 같은 대본, 같은 스토어, 여는 방식만 바꿔 잰 값:

| 대본: 매 턴 새 도구(결과 없이 죽는다) | 스레드(실측) | `turnDidWork` |
|---|---|---|
| 재개를 **렌더러가** 연다(`begin`) | `user TG(tg2:1) assistant! user TG(tg5:1) assistant!` | **참** — 엔진과 일치 |
| 재개를 **엔진이** 연다(`user-echo`) | `user TG(tg2:2) assistant! user assistant!` | **거짓** — 엔진은 참(71발) |

R2가 실패시킨 그 71 대 2가 **`tool_use` 문으로 한 번 더** 서 있는 셈이다. 다만 이번에는
**계수 궤적이 안 갈린다**: `user-echo`가 재개를 여는 표면은 본채팅뿐이고 거기서는
`resumeOwner:"engine"`(`lite.rs:175`) 때문에 `turnDidWork`를 **아무도 안 읽는다**. 렌더러가
표를 드는 표면(멀티 패널 · 팝아웃 · 추가 창)은 자기 `send`로 쏘므로 늘 `begin`이다. 그래서 이번
라운드의 판정은 안 뒤집는다 —— 그러나 두 사실은 남는다:

1. **화면은 이미 거짓이다.** 밤샘 재개 71턴이 연 도구 행이 전부 **첫 턴 그룹**에 쌓이고,
   그 아래 「이어서」 말풍선 71개는 텅 빈 채로 남는다.
2. **파리티의 근거가 규약 하나에 매달려 있다.** 「렌더러가 여는 재개는 반드시 `begin`」이
   깨지는 날(엔진 큐 드레인이 그 표면의 턴을 여는 어떤 배선이든) 같은 71 대 2가 곧바로 산다.
   `turnDidWork`가 「두 축의 정의 그 자체」라면, 그 정의는 **여는 방식과 무관**해야 한다.

**다음 라운드 후보**: `user-echo`(와 `result`)에서 `openGroupId`를 비우는 한 줄. 판정 로직이
아니라 스토어 한 줄이고, 위 두 사실을 같이 없앤다.

## 5. 부수 관찰(이 라운드 과녁 아님 · 기록만)

* **§14.2의 47발은 아직 「정의」다.** 매 턴 산출을 내며 같은 벽에 계속 부딪히면 빈손이
  **연달아 둘** 오기 전까지 안 접힌다 —— 내 실측으로 12시간 **71발**(매 턴 글자) /
  **47발**(두 턴에 한 번 빈손 · attempts 1) / **53발**(세 턴에 한 번). RVERD의 원사고가
  「5시간 창 하나에 27발」이었는데 이 판은 ≈5시간당 20~30발이다. **파리티는 안 깨져 있다**
  (렌더러도 같은 답). 빌더가 「경계 밖」이라며 미룬 것은 R2가 물어본 그 질문이고, **지금은
  RCAP의 「자동은 최대 2발」이 보증이 아니라 조건부 성질**이라는 사실만 남는다.
* **부팅 재장전 비대칭** — `reload_state`가 `attempts: 0`을 심고(`runtime.rs:626`) 렌더러는
  `sanitizeHold`가 계수를 살린다. 재시작마다 눈감은 2발이 새로 생기는 자리이고 R28c부터의 것.
* **`rate_limit_event` 경로**와 **한도 문구가 어시스턴트 텍스트로 오는 판**은 R2 §5 그대로.
* **라이브 앱 주행 없음**(창 하나가 5시간). 엔진은 가상 시계, 렌더러는 실제 리듀서 구동으로 대체.

## 6. 결론

* **닫힌 것**(내 손으로 확인): R2 §3.3의 최대 격차. `tool_result`가 턴 경계를 넘는 P12와
  짝 없는 도구 결과가 **대조군 71발 → HEAD 2발·접힘**으로 뒤집혔고, 인과는 그 한 조각이
  특정한다. 반대 방향(과잉 절단)은 대조군에서도 초록. R2 §3.2 대조표의 불일치 줄이 사라져
  **실제 스토어로 잰 15줄이 전부 일치**한다. R2가 지적한 사실관계 오류 셋도 §14에서 정정됐고
  (원문은 틀린 채로 남기고 정정을 따로 —— 좋은 규약), 계기 눈금(`spawns`→프롬프트 줄)도 고쳐졌다.
* **회귀 없음**: cargo 6종 · `wcap_limit_streak` 22/22 · `poc-limit-resume` 249/0 ×3 ·
  라이브 하네스 11/0 · 8/0 · typecheck 3종. 밤샘 주행 12발(안 잘림) · 헛발질 2발(접힘+버튼) ·
  배너 문구는 그 착지에서만 뜬다.
* **남은 최대 격차**: 「이 턴이 연 도구 그룹」이라는 **공통 정의가 여는 방식에 매달려 있다**
  (§4.3) —— 엔진이 연 재개 턴에서는 스토어가 그 턴의 도구를 앞 턴 그룹에 넣어 같은 71 대 2가
  선다. 지금은 그 표면에서 아무도 안 읽어 계수는 안 갈리지만, **화면은 이미 거짓**이고 파리티는
  규약 하나에 얹혀 있다. 그다음이 §14.2의 47발 표다.
