### 3.1 ★칩이 마운트마다 증발한다 (A9 · A6)

```
턴 뒤            : {"text":"1 · 1","tip":"MCP 1개 연결 · 스킬 1개 · 클릭해 자세히"}
「크게 보기」 중  : null          ← 카드에 칩 자체가 없다
「원래 크기로」 뒤: null          ← 그리드로 돌아와도 없다
팝아웃 첫 진입    : null          ← 그 창에서 한 턴 더 태워야 `1 · 1`이 뜬다
```

원인은 설계 그대로다. 값은 `EngineEvent{type:'tooling'}` **푸시 한 장**뿐이고 그것을
`McpSkillView`가 자기 `useState`에 담는다(세션 스토어를 일부러 안 거친다 — 보고서 §2.1).
그런데 껍데기가 갈리면(`크게 보기`=오버레이 카드로 이동 · 팝아웃=다른 창 · 복귀=그리드 재마운트)
컴포넌트가 새로 마운트되고 state는 `null`에서 시작한다. **셸에는 `Wire::env`가 그대로 있는데
질의 채널(`chat:tooling-get` 류)도, 구독 시 리플레이도 없다.**

- 헤더의 다른 표식은 안 그런다: 폴더 칩은 영속 meta에서, 상태 칩은 세션 스토어에서 온다.
  **증발하는 것은 M9 칩 하나뿐이다.**
- 재시작 때 안 되살리는 결정(§2.1 "지난주에 붙어 있던 MCP 서버")은 옳다. 그러나 그 결정이
  **같은 세션 안의 재마운트까지** 지울 이유는 없다. 런타임 전용 캐시(모듈 스코프 Map · panelId
  키)나 구독 리플레이 한 줄이면 원칙을 안 깨고 산다.

### 3.2 ★`mcp_norm`은 이번 라운드에 **처음** 실측됐고, 비BMP에서 틀린다

`wire.rs::mcp_norm`("비 `[A-Za-z0-9_-]` → `_`")은 `sdk.d.ts` 주석에서 온 규칙이고 단위 테스트
`mcp_tool_prefix_matches_the_normalized_server_name`이 `my.co tools`로 못 박았다. 그런데
**빌더가 실 CLI에 물린 이름은 `ccg-probe-a`·`ccg-probe-b` — 정규화할 문자가 하나도 없다.**
규칙 자체에는 실측 근거가 없었다. 실 CLI(0.3.241)에 5종을 물렸다(`critic-m9-norm.mjs`):

| 설정 이름 | 실 CLI 접두사 | `mcp_norm` 기대 | |
|---|---|---|---|
| `my.co tools` | `mcp__my_co_tools__` | 같음 | 일치 |
| `srv__dbl` | `mcp__srv__dbl__` | 같음 | 일치(뒤에서 가르기 근거 확인) |
| `한글서버` | `mcp________` | 같음 | 일치(BMP는 1자 = 1단위) |
| `UPPER-Case` | `mcp__UPPER-Case__` | 같음 | 일치(대문자 보존) |
| **`emoji🚀srv`** | **`mcp__emoji__srv__`** | `mcp__emoji_srv__` | **불일치** |

CLI(JS)는 정규식이 **UTF-16 코드 단위**를 돌아 서로게이트 쌍을 `_` **두 개**로 바꾸고,
`mcp_norm`은 Rust `chars()`(유니코드 스칼라)라 `_` **하나**를 만든다. 결과: 비BMP 문자가 든
서버 이름은 도구가 **조용히 사라진다**(행은 「연결됨」인데 도구 이름도 `도구 N` 배지도 없다).
좁은 자리지만 단위 테스트가 "이걸 못 박았다"고 적어 둔 바로 그 자리다. 고침은 한 줄이다
(`c.len_utf16()`만큼 `_`).

부수 관찰(A2): 도구 이름에 `__`가 있으면(`mcp__srv__dbl__get__thing`) 뒤에서 가르는 규칙이
서버를 `srv__dbl__get`으로 읽어 그 도구가 목록에서 빠진다 — 코드 주석이 인정한 거래이고,
대가는 **틀린 도구 수**(위 판에서 `도구 1`)다. 서버 목록에 없는 접두사(`mcp__ghost__…`)도
조용히 버려진다.

### 3.3 칩·툴팁이 `connected`/`failed` 밖의 상태를 안 센다 (A1 · A2)

```
A1 서버 10 = 연결7 · 실패1 · 인증필요1 · pending1
  칩   : "7/10 · 50"                              ← 분모는 정직하다
  툴팁 : "MCP 7개 연결 · 2개 실패 · 스킬 50개"     ← 7+2 = 9. **pending 1개가 없다**
                                                    (그리고 `needs-auth`가 「실패」로 합산됐다)
A2 서버 5 = 연결4 · status 필드 없음1
  칩   : "4 · 5"  ← `bad === 0`이라 분모가 안 뜬다. 5번째 서버는 칩에도 툴팁에도 없다
```

칩 본문은 `bad > 0`일 때만 분모를 드러내고(`live/total`), 툴팁은 `live`·`bad`·`off` 셋만
읽는다. 그래서 `pending`·`disabled`·`unknown`은 **숫자에서도 문장에서도 사라진다** —
"연결 중"과 "안 붙었음"이 화면에서 같은 얼굴이 된다. 보고서가 세운 원칙
(「실패는 숫자 하나로 가려지면 안 되는 사실이다」)이 나머지 상태에는 적용돼 있지 않다.
`needs-auth`를 「실패」로 세는 것도 같은 계열이다 — 행은 「인증 필요」라고 옳게 적으면서
툴팁만 「실패」라 말한다(사용자가 할 일이 다르다: 하나는 로그인, 하나는 설정 고치기).

곁들여, **칩과 카드의 수가 어긋난다**(A5): 끈 항목이 있으면 칩은 `1 · 1`(off 제외)인데
섹션 머리는 `MCP 서버 2` / `스킬 2`(off 포함)다.

### 3.4 ★팝오버 2장이 동시에 뜬다 — 보고서 §2.2의 반증 (A10)

보고서 §2.2: *"두 팝오버(도구 환경·작업 폴더)는 … 바깥 mousedown으로 닫히므로 **동시에 열리지
않는다**(서로의 칩 클릭이 상대에겐 바깥 클릭이다)."* 실측은 반대다:

```
도구 환경 팝오버 열기 → 폴더 칩 클릭(mousedown → mouseup → click)
  .wb-pop 개수 : 2
  좌표         : [{"head":"도구 환경 wA","x":353,"y":95,"w":300,"h":217},
                  {"head":"작업 폴더",  "x":353,"y":95,"w":300,"h":214}]
  겹침         : 64,200px²  (= 완전 포개짐)
```

이유: 폴더 칩의 래퍼 `.hfold`가 `onMouseDown={(e) => e.stopPropagation()}`이고, 도구 팝오버의
바깥닫힘은 **`window` mousedown**이다. React가 루트 컨테이너에서 네이티브 전파를 끊으므로
`window`까지 오지 않는다 — "상대에겐 바깥 클릭"이라는 전제가 성립하지 않는다. 화면에서는 뒤에
깔린 도구 팝오버가 폴더 팝오버에 완전히 가려지고, 도구 칩은 `.on`(액센트) 상태로 남는다.

행은 `.wb-prow(.done/.err)`, 빈 상태는 `.ag-none`. 2.6.2에 없던 신기능이지만 **새 낱말을 하나도
안 만들었다**. 420px급(402px 실측)에서도 잘림 0·헤더 넘침 0이고, 칩이 제목에서 가져가는 폭은
40px다(A8). 팝오버는 좁은 패널에서도 `.ma-p-head` 앵커 덕에 패널 밖으로 안 나간다(이탈 0px).

**정보 밀도: 조건부.** 현실 밀도(내 실홈 = 서버 1~2 · 스킬 15~17)에서는 좋다. 한 행이
`이름 · 상태 · 도구이름`(MCP) / `/이름 · 설명 한 줄 · 스코프 배지`(스킬)로 **행 하나가 한
질문에 답한다.** 941자 설명을 110자로 자른 판단(§5-⑤)도 실측 139자로 확인했다. 문제는 위쪽:

```
서버 10 + 스킬 50 → 행 60 · 콘텐츠 높이 3,180px · 카드 340px · 한 화면 6행
```

- 검색·필터 없음 · 섹션 접기 없음 · `.hsec`가 sticky가 아니라 **스크롤하면 "여기가 어디"가 사라진다**.
- MCP 섹션이 먼저라 스킬 목록은 **처음부터 화면 밖**이다(서버가 10개면 11번째 행부터가 스킬).
- 칩이 `· 50`으로 규모를 미리 알려 주는 점은 정직하다. 그래서 이건 결함이라기보다 **다음
  라운드의 값**이다: 접기(기본 MCP만 펴기) 또는 한 줄 필터.

## 5. 보고서·커밋의 사실 오류 / 정정 (양방향)

**가. `--app` 단언은 11건이 아니라 13건이다.** 행복 경로 `ok(...)` 13개(+실패용 1). 과소 신고라
해는 없지만, 「단언 N건」을 판정 근거로 쓰는 문서라 숫자는 맞아야 한다.

**나. §1의 "엔진 0.3.241"은 와이어 갈래에서 재현되지 않는다.** `poc-mcpskill.mjs`의 기본값은
`CCG_ENGINE ?? '0.3.239'`다. 부록의 재현 명령(`node scripts/poc-mcpskill.mjs`)을 그대로 치면
**0.3.239**로 잰다(내 재실행이 그 판이고, 값은 §1과 동일했다 — 결론은 안 바뀐다). `--app`만
앱의 `activeVersion`(0.3.241)을 쓴다.

**다. §6 「off 행을 실물에서 만들 경로가 아직 없다」는 사실이 아니다 — 있고, 된다.**
설정 UI(`mcp:list`·`mcp:set-enabled`)가 없는 것은 맞지만, 그 값이 사는 축은
`chat:identity-set{tools:{deniedMcp,skillOverrides}}`이고 **그 채널은 3.0 셸에 구현돼 있다.**
실물 2패널에서:

```
정책 적용(applied · revision 1) 뒤 **재스폰 없이** 1.5초 안에
  패널A 칩  : "1 · 1"  툴팁 "MCP 1개 연결 · 1개 꺼짐 · 스킬 1개"
  패널A 행  : ["srv-on · 연결됨 · echo · 도구 1", "srv-off · 설정에서 껐어요"]
              ["/s-keep · 남는 스킬 · 프로젝트", "/skill-off · 설정에서 껐어요"]
  패널B(정책 없음) : off 행 0건 — 옆 패널로 안 샌다
```

허브가 매 tick `set_policy`를 부르고 바뀔 때만 재방출하는 설계가 **실물에서 정확히 그대로
작동한다.** 보고서는 자기 성과를 과소 신고했다(그리고 그 바람에 이 경로는 R20에서 아무도
안 밟았다 — 내가 처음 밟았다).

**라. §6 「`commands_changed`는 단위 테스트만이 근거」도 지금은 아니다.** 푸시를 **턴 한복판**에
넣으면 화면까지 닿는다(A4c · 와이어 계수 `commandsChanged:1`). 못 닿는 것은 `result` **뒤**의
푸시뿐이고, 그 이유가 "턴 끝에 CLI가 죽는다"라는 보고서의 진단도 와이어 계수 0장으로 확인됐다.
즉 arm은 살아 있고, 죽은 것은 **그 프레임이 오는 시점**이다.

**마. §3의 팝오버 머리 인용이 실측과 다르다.** 보고서는 「도구 환경 · A」/「· B」로 적었지만
실물 DOM은 **소문자**다(빌더 자신의 `app-dom.json`도 `"head": "도구 환경 · a"`). 원인은 코드다:
`read_init_env`가 `system/init.cwd`를 쓰는데, 앱은 CLI를 **정규화된(소문자) cwd**로 띄우므로
CLI가 소문자를 되돌려 준다. 그래서 같은 헤더 안에서 폴더 칩은 `A`, 도구 팝오버 머리는 `a`가
된다(실 사용자 폴더면 `AgentCodeGUI` 옆에 `agentcodegui`). 표시용 이름은 패널 meta의 cwd에서
따오면 그만이다.

## 6. 남은 위험(제품 결함 아님 · 기록만)

1. **플러그인 스킬의 조인 키.** `init.skills`의 플러그인 스킬은 정규 이름(`my-plugin:my-skill`)
   으로 올 수 있고(SDK `initialize.skills` 주석), 커맨드 사전이 다른 표기를 쓰면 설명이 통째로
   빈다. 합성 프레임에서는 `/myplug:skill`이 정상 렌더됐지만, **실 플러그인으로는 아무도 안 쟀다**
   (보고서도 `plugins: []`만 봤다고 적어 뒀다).
2. **중복 스킬 이름**이 오면 같은 `key`로 두 행이 그려진다(A2에서 재현 — 크래시는 없다).
3. **`aliases`**(SlashCommand의 필드)는 안 쓴다. `/cost`·`/stats` 같은 별칭은 목록에 안 뜬다.
4. **본채팅·추가 채팅 미부착**은 보고서가 스스로 적은 범위 밖이다(요구가 「멀티채팅 기준」).
   다만 `McpSkillView`는 `ma:event`(패널 전용 채널)에만 붙어 있어, 두 표면에 붙일 때는 구독
   주소를 하나 더 만들어야 한다 — 지금 구조가 그 확장을 막지는 않는다.
