## 3. ★ 토큰 안전 감사 — **C1 (치명)**

### 3.1 빌더 자신이 적은 계약

같은 커밋의 `crates/ccg-auth/src/bin/ccg_auth_probe.rs:160-172`:

> **리프레시하지 않는다**가 이 함수의 계약이다. 액세스 토큰이 이미 만료됐으면
> `skipped: token_expired`로 끝낸다 — 교환은 refresh 토큰을 **서버에서 회전**시켜서,
> 복사본 홈에서 돌리면 원본 홈의 토큰이 그 순간 죽는다(**되돌릴 수 없는 부작용**).

그래서 프로브에는 문이 있다: `account_access_token()`이 `None`이면 **거기서 끝낸다.**

### 3.2 제품 경로에는 그 문이 없다

```text
[워커 스레드 ccg-acct-switch]
  acct_switch.rs:266  fetch(email)
   └ net.rs:170       fetch_account_usage(email)
      └ net.rs:171       access_token(email)                    ← 문이 없다
         ├ claude::account_access_token()  → None(만료)
         ├ claude::refresh_token()         → Some
         └ net.rs:123    for req in usage::refresh_requests(&refresh) { send(&req) }
                         = POST /v1/oauth/token {grant_type:"refresh_token"}   ★ 서버 회전
```

**후보는 "노는 계정"이고, 노는 계정은 정의상 액세스 토큰이 만료돼 있다**(발급 3600초 ·
갱신은 그 계정으로 CLI를 띄울 때만). 즉 이건 예외 경로가 아니라 **정상 경로**다.

### 3.3 증명 — 네트워크 0건으로

`docs/critic/tools/critic-m11-token.rs`(격리 `CCG_HOME` · `CCG_NO_NET=1`). 판별식:
`Disabled`는 **`send()`까지 갔다**는 뜻이고, `access_token()` 안에서 `send`가 불리는
자리는 리프레시 요청 하나뿐이다. `NoToken`은 **시도조차 안 했다**는 뜻이다.

```text
[T] CCG_HOME=…\ccg-m11c-auth-18200  CCG_NO_NET=true
[T] access_token(idle)=Some(Disabled)   ← 만료 액세스 + 살아 있는 refresh  ★ 교환하러 갔다
[T] access_token(dead)=Some(NoToken)    ← refresh 없음(대조군)             교환 안 함
[T] fresh_ok=true                       ← 신선 토큰(대조군)                 교환 불필요
[T] fetch_account_usage(idle)=Some(Disabled)   ← acct_switch::fetch가 부르는 바로 그 함수
[T] refresh req: POST https://console.anthropic.com/v1/oauth/token  grant_type="refresh_token"
test the_product_path_does_attempt_a_refresh_exchange_on_an_idle_account ... ok
```

### 3.4 폭발 반경

1. **부팅마다 전 계정.** `acct_switch.rs:116` — `Switcher::start()`가 `enabled()`면 곧바로
   `kick()`한다. 한도에 걸리지 않아도, 사용자가 아무것도 안 해도, **앱을 켜는 것만으로**
   등록 계정 전부의 usage를 조회하고 만료된 것들의 토큰을 회전시킨다.
2. **예산 문 ②가 실제로는 없다**(→ C4). `collect()`는 `order` 전체를 돈다 — 현재 계정도,
   이미 거쳐 온 계정도 조회한다. `Switcher`에는 그 둘을 알 필드가 아예 없다.
3. **회전 결과 유실 = 계정 잠금.** `net.rs:151-153`
   ```rust
   if let Some(next) = next { let _ = claude::persist_refreshed(email, &next); }
   ```
   `apply_refresh`가 `None`이거나(base가 JSON 객체가 아님) `persist_refreshed`가 `Err`이면
   **서버에서 이미 죽은 옛 토큰만 남는다.** 에러는 `let _`로 삼켜지고 로그 한 줄도 없다.
   (`persist_refreshed`는 폴더를 먼저 쓰므로 부분 실패는 살아남지만, `create_dir_all`·
   `write_file_atomic` 실패는 그대로 재로그인이다.)
4. **`collect()` 중에 깨어난 CLI.** `busy`는 루프 **진입 전 한 번만** 읽는다
   (`acct_switch.rs:226`). 6계정 × 1.2초 간격이면 이 루프는 수 초~십수 초다. 그 사이
   턴을 시작한 계정도 조회·회전 대상이다 — 살아 있는 CLI 밑에서 그랜트를 돌린다.
5. **2.6.2에는 있고 여기에는 없는 것**: `src/main/auth.ts:411`의 `refreshInflight`
   단일 비행("같은 계정 동시 요청을 합쳐 **이중 회전**을 막는다"). 3.0에서는 호출자가
   워커 스레드 하나뿐이라 지금은 우연히 안전하지만, 그 성질은 코드에 안 적혀 있다.

### 3.5 공정하게 — 이건 M11이 **발명한** 위험은 아니다

2.6.2도 같은 교환을 한다(`auth.ts:412 freshAccountToken` ← `accountsUsage()` ←
`useLimitResume.ts:97`). 그러니 *동작*은 제품 계열의 선례가 있다. **새로운 것은 셋**이다:
① 3.0 러스트 앱에 네트워크가 **처음** 생겼고(그 유일한 호출자가 M11이다),
② **부팅 프리웜**이라 사용자 조작과 무관하며,
③ **리포트가 이 경로를 「리프레시 안 함」으로 적어** 다음 사람이 안전하다고 믿게 만든다.

> 커밋: *"실 HTTP는 1건만 썼다: GET /api/oauth/usage → 200 · 460ms(복사본 홈 · **리프레시
> 안 함** — 교환은 refresh 토큰을 서버에서 회전시켜 원본 홈의 토큰을 죽인다)"*
>
> 참인 문장이다 — **그 한 번의 손 주행에 대해서만.** 시드 계정의 `expiresAt`이 2096년
> (`ccg_auth_probe.rs:52 far_future`)이라 하네스 6판도 이 가지를 한 번도 안 밟았다.

### 3.6 최소 수선(제품 코드는 안 고쳤다 — 제안만)

- `net::fetch_account_usage`에 프로브와 **같은 문**을 단다: `account_access_token()`이
  `None`이면 `Err(NoToken)`으로 끝낸다(= 그 계정은 `usage_unknown` → 후보 아님).
  잃는 것: 오래 논 계정의 게이지. 얻는 것: 자동 경로의 회전 0.
- 회전이 필요하다고 판단되면 최소한 ⑴ `persist_refreshed`의 `Err`를 **소리 내고**
  ⑵ 실패 시 그 계정을 잠금 후보로 표시하며 ⑶ 단일 비행을 명시한다.

## 4. 공격 — 빌더 재생 10판이 안 잡는 자리

도구: `docs/critic/tools/critic-m11-attack.rs`(핀 워크트리의 `crates/ccg-engine/tests/`로
복사해 실행). **3판 전부 red = 3건 전부 실재.**

### C2 (중대) — 스탬피드: 규칙 ①「노는 계정만」이 뚫린다

허브 규약(`hub.rs::pump`)은 `set_busy(burning_accounts())`를 **펌프 한 바퀴에 한 번,
슬롯 tick 앞에서** 돈다. 그래서 같은 바퀴 안에서 채팅1이 b로 옮겨 스폰해도 채팅2의
`pick`이 보는 busy에는 b가 없다. 스냅샷 usage도 그대로다. **예약(reservation)이 없다.**

이건 좁은 레이스가 아니다. 워커 스냅샷이 도착하는 순간, **같은 소진 계정에 묶여
대기 중이던 N개 채팅이 동시에 열린다** — 그 펌프에서 전원이 같은 1등을 고른다.

```text
[A3] chat-1=b@x  chat-2=b@x  picks=[("chat-1","b@x"),("chat-2","b@x")]
     assertion `left != right` failed: ★ 두 채팅이 같은 계정으로 갈아탔다
```

결과가 정확히 규칙 ①이 막으려던 상태다 — *"둘이 한 창을 나눠 쓰다 **둘 다** 막힌다."*
그리고 둘 다 막히면 둘 다 다음 후보로 몰려간다(연쇄).

### C3 (중대) — 유령 대기 문장: 수정 ④가 **다른 문으로** 재발한다

`hold_notice_due`를 내리는 자리는 두 곳뿐이다(전환 성사 · `emit_hold_notice`). 그런데
대기표는 **다른 세 경로**로도 죽는다(§7.3 계정 변경 · `Cmd::HoldCancel` · …). 그리고
`check_hold:3048`의 미뤄 둔 문장 블록은 **`hold.is_some()`을 안 본다.**

```text
[A1] 대기문장=1  hold=false
     notices=["계정을 바꿔서 대기표를 취소했어요",
              "사용 한도에 걸려 대기합니다 — 언제 풀리는지 알 수 없어 잠시 뒤 다시 확인할게요."]
[A2] 대기문장=1  (Cmd::HoldCancel = 사용자가 '자동 이어서 끄기'를 누른 뒤)
```

리포트 §2-④가 죽였다고 적은 **바로 그 모양**(연달아 뜨는 두 줄 중 뒤가 앞을 거짓으로
만든다)이 순서만 뒤집혀 돌아왔다. 게다가 표가 이미 없으니 `resets_at`도 잃어
「언제 풀리는지 알 수 없어」 변종이 나간다 — 알던 시각까지 버린다.

수선 한 줄: `if self.hold_notice_due && self.hold.is_some() { … }`
(또는 `hold`를 `None`으로 만드는 세 자리에서 플래그를 같이 내린다).

### 뮤테이션 — "고쳤다"가 정말 잠겼나

핀 워크트리 사본에 결함을 **되돌려 심고** 빌더의 재생 10판을 돌렸다. red면 잠긴 것이다.

## 6. native-tls — **검증 완료, 제안 diff** (다음 라운드 첫 항목)

리포트 §5가 남긴 숙제. **실제로 되고, 실제로 줄어든다.**

| 빌드 | 크기 | M11 비용 | 비고 |
|---|---|---|---|
| **M11 이전**(`9eba6fa` = `63fa3df^`) | **5,624,320 B** (5.62MB) | — | 리포트의 "5.63MB"와 사실상 일치 |
| 핀(`f404deb`) rustls + 번들 루트 | **6,733,824 B** (6.73MB) | **+1,109,504 B** | 리포트 "+1.08MB"와 일치. 타깃 디렉터리 2곳에서 **바이트 동일** |
| **native-tls(schannel)** | **5,842,944 B** (5.84MB) | **+218,624 B** | 같은 워크트리·같은 커밋, 아래 diff만 |
| **회수량** | **−890,880 B (−13.2%)** | M11 비용의 **80%** | +1.11MB → **+0.22MB** |

동작 확인(실 HTTP 1건, 무인증): `GET https://console.anthropic.com/v1/oauth/token`
→ **405 · 258ms**. TLS 핸드셰이크가 schannel로 정상 성립한다.

```diff
--- a/crates/ccg-auth/Cargo.toml
+++ b/crates/ccg-auth/Cargo.toml
-net = ["dep:ureq"]
+net = ["dep:ureq", "dep:native-tls"]
@@
-ureq = { version = "2.12", default-features = false, features = ["tls"], optional = true }
+# rustls + 번들 루트 인증서 대신 **OS 스토어(schannel)** 를 쓴다 — 실측 −890,880 B.
+# 인증서 신선도도 OS가 맡는다(번들은 앱을 새로 내야 갱신된다).
+ureq = { version = "2.12", default-features = false, features = ["native-tls"], optional = true }
+native-tls = { version = "0.2", optional = true }

--- a/crates/ccg-auth/src/net.rs
+++ b/crates/ccg-auth/src/net.rs
@@ fn send(req: &HttpRequest) -> Result<HttpResponse, NetError> {
     let agent = ureq::AgentBuilder::new()
+        // ureq 2.x는 native-tls를 자동으로 안 쓴다 — 커넥터를 손으로 준다.
+        .tls_connector(tls_connector()?)
         .timeout(Duration::from_millis(req.timeout_ms))
         .redirects(0)
         .build();
+
+/// 커넥터는 프로세스당 하나면 된다(핸드셰이크마다 만들 이유가 없다).
+fn tls_connector() -> Result<std::sync::Arc<native_tls::TlsConnector>, NetError> {
+    static TLS: std::sync::OnceLock<Result<std::sync::Arc<native_tls::TlsConnector>, String>> =
+        std::sync::OnceLock::new();
+    TLS.get_or_init(|| native_tls::TlsConnector::new().map(std::sync::Arc::new).map_err(|e| e.to_string()))
+        .clone()
+        .map_err(NetError::Transport)
+}
```

내가 측정한 빌드는 `tls_connector`를 `send`마다 만드는 형태였다(그래도 258ms). 위
`OnceLock` 형태는 그 낭비만 줄인 것이고 크기에는 영향이 없다.

**대가 하나는 적어 두자**: schannel은 Windows 루트 저장소를 믿으므로 사내 MITM 프록시의
루트도 신뢰하게 된다(rustls 번들은 거절했다). 이 앱은 Windows 전용이고 사용자 대부분에게
그건 **기능**이지만, 선택은 선택이다.

## 7. 남은 위험 (제품 결함은 아니지만 다음 사람이 알아야 하는 것)

| # | 무엇 |
|---|---|
| R-1 | **전환 직후 재검증이 없다.** `LimitProbe`는 셸에 **미배선**이고(`src-tauri` 전체에 `with_limit_probe` 0건) `try_auto_switch`는 훅을 안 본다. 캐시가 2분 낡아 소진된 계정을 골라도 스폰 한 번을 태우고서야 안다. 상한은 `switch_tried`가 잡아 **최악 N스폰**(계정 수)이고 무한은 아니다 — 재생 ④'가 그 착지를 잡는다 |
| R-2 | **창이 전부 `Rolled`면 여유 100%**(`switch.rs:218 unwrap_or(100)`). usage 응답 모양이 바뀌어 파서가 전부 `None`을 내면 **모든 계정이 만점 후보**가 된다. 의도된 관대함이지만, 그 실패는 조용하다 |
| R-3 | **되돌린 뒤의 침묵.** 사용자가 배너의 되돌리기로 A로 돌아오면 `switch_tried={A,B}`가 그대로라 그 에피소드에서는 전환이 다시 안 열린다 — 화면에 그 이유가 없다(D7 경계) |
| R-4 | **`last_plan`이 전역**이다(`engine:debug`의 `accountSwitch.picked/skipped`). 채팅이 여럿이면 마지막에 물은 채팅의 답만 보인다 — 진단이 조용히 거짓말한다 |
| R-5 | 재조준(수정 ③)은 **같은 소진 계정을 손수 고른 예약**도 옮긴다(축 비교라 구분이 안 된다). `OnDrift`가 배선되면 사라질 경계 |
| R-6 | `poc-live-chat.mjs --tag=m11r1`(리포트 §4)은 **내가 안 돌렸다** — 미검증 |
