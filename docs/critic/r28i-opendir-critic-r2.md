# R28i OPENDIR 확인 크리틱 R2 — 다섯 칸은 내 손에서도 닫혔다. 그런데 **그 닫힘을 지키는 못이 하나도 없고**, 「남은 비대칭 하나」는 이번에도 하나가 아니다

판정 대상: `1ec1964`(N3 구현) · `6028521`(다듬기) · `57e55e6`(확인 크리틱 R1 지적 수정).
이 라운드의 확인 크리틱 R2는 **앞서 두 번 API 인증 장애(403)로 죽어 판정이 미완**이었다 — 그 자리를 대신한다.

판정 규율: 빌더의 보고서(`docs/parity-fix-opendir-r1.md`)·커밋 메시지·하네스
(`scripts/poc-opendir.mjs`·`poc-opendir-crit.mjs`)·결과 파일(`docs/critic/opendir-*.json`),
그리고 **확인 크리틱 R1의 수치**까지 전부 근거로 쓰지 않았다. 아래 수는 내가 다시 굽고,
내 계기로, 내 격리 홈에서 잰 것이다. **레포 코드 수정 0** — 이 판정문 한 파일만 쓴다.

## 2. 체크리스트 항목별 실측

### 2-1) 떠 있는 앱 + 두 번째 실행(폴더 인자) — ✅ 닫힘

`ProjA → ProjB → ProjA` 3회, 창이 보이는 상태.

| | 판정 `57e55e6` | 대조군 `5d6b5a2` |
|---|---|---|
| 폴더 도착 | **3/3** · **26 / 24 / 22 ms** | **0/3** — 9초 창 내내 `폴더 선택` 그대로 |
| chat-head | `폴더 선택 → ProjA → ProjB → ProjA` 실제 전환 | 불변 |
| 두 번째 프로세스 | exit 0 · 18/19/17 ms에 사망 · 새 창 0 | exit 0 · 17/15/14 ms · 새 창 0 |

대조군에서 **폴더가 조용히 사라지는 것**(창은 앞으로 오고 폴더만 없어진다)을 그대로 재현했다.

### 2-2) ★트레이에 숨어 있을 때 — ✅ 닫힘

| | 판정 | 대조군 |
|---|---|---|
| 보이는 창 (WM_CLOSE → 두 번째 실행) | **1 → 0 → 1** (3/3) | 1 → 0 → 1 (3/3) |
| raise 지연* | 299 / 301 / 326 ms | 282 / 426 / 304 ms |
| 폴더 도착 | **3/3 · 54 / 40 / 33 ms** | **0/3** |
| 숨김 + **못 여는 폴더**(`Denied`) | 창이 서고(323ms) 카드가 **보이는 화면에** — `440×202` · `visibility:visible` · `document.hidden=false` · chat-head 불변 | 아무 일도 없음 |

\* raise 지연은 PowerShell 창 열거 폴링(60ms 간격)에 묶인 **상한**이다. 두 exe가 같은 잣대라 비교만 유효.

### 2-3) 콜드 vs 두 번째 실행이 같은 착지인가 (다섯 칸 · 각 3회) — ✅ 닫힘

같은 폴더 `ProjB`에 두 길로 닿게 하고(콜드=인자로 기동 / 웜=A로 켠 뒤 두 번째 실행이 B) 비교.
탐색기 칸은 백쿼트(사이드바⟷탐색기)를 합성 키로 눌러 켠 뒤 읽었다.

| 칸 | 콜드 ×3 | 웜 ×3 | 같은가 |
|---|---|---|---|
| cwd | `…\ProjB` | `…\ProjB` | **같다** |
| chat-head 전체 텍스트 | `…\ProjB 1 2 3 4 5 6` | 〃 | **같다** |
| 사이드바 | `채팅이 없어요` | 〃 | **같다** |
| 탐색기 트리 루트 | `["beta_dir","BBB_beta.txt"]` | 〃 | **같다** |
| 활성 채팅(디스크 `chats-v3/index.json`) | 채팅 1개 · `activeChatId` = 그 하나 | 〃 | **같다** |
| 카드 | 없음 | 없음 | **같다** |

세 번씩 모두 자기 안에서도 흔들리지 않았다(`coldStable`·`warmStable` 전부 true).
채팅 id 자체는 홈마다 새로 나므로 「하나인가 · 활성이 그것인가」로 비교했다.

### 2-4) ★못 읽는 폴더가 「비어 있음」이라 거짓말하는가 — ✅ **닫혔다**(R1의 최대 격차)

웜(두 번째 실행). 착지 기준선은 `ProjA`.

| 인자 | 판정 `57e55e6` | 수정 전 `6028521` |
|---|---|---|
| **못 읽는 폴더**(deny ACL) | **카드 28ms** — "‘…\Denied’ **안을 읽을 권한이 없어요**…" · 착지 **안 함** · chat-head 불변 | **카드 없음. 그 폴더로 착지**(chat-head가 `…\Denied`로 바뀐다) |
| 없는 경로 | 카드 22ms(not-found) · 불변 | 카드 478ms · 불변 |
| 파일 | 카드 25ms(not-a-dir) · 불변 | 카드 24ms · 불변 |
| **공백만**(`"   "`) | **카드 24ms**(empty) · 불변 | **카드 없음 · 아무 일 없음** |
| 상대 경로 | 카드 21ms(not-found) · 불변 | 카드 22ms · 불변 |
| **빈 폴더**(과잉 차단 감시) | **열린다**(착지) · 카드 없음 | 열린다 |

콜드(기동 인자)도 같은 잣대로 답한다 — 여기가 R1이 「이월」로 남긴 D3다.

| 콜드 인자 | 판정 | 수정 전 |
|---|---|---|
| 못 읽는 폴더 | 카드 · cwd `폴더 선택`(**안 연다**) | **카드 없음 · 그 폴더로 착지** |
| 없는 경로 / 파일 / 공백 / 상대 경로 | **넷 다 카드** · 착지 안 함 | **넷 다 침묵** |
| 빈 폴더 | 착지 | 착지 |

원시 호출도 같은 답을 준다:
`app:open-directory("…\Denied")` → 판정 `{"ok":false,"reason":"denied","path":…}` /
수정 전 `{"ok":true,"dir":"…\\Denied"}`. 공백 `{"ok":false,"reason":"empty"}`,
인자 없음도 `empty`, 정상 폴더 `{"ok":true,"dir":…}`.

즉 **커밋 제목 「못 읽는 폴더는 「비어 있음」이 아니라 못 읽는 폴더다」는 참이다.**

### 2-5) ★부팅 0.8초의 폴더 · 콜드 청소 · 인계 잔해 — ✅ 닫힘

**(a) 경주 스윕** — 매 회 새 프로세스 · 목표를 A↔B로 뒤집어 거짓 초록을 막았다.

| 두 번째 실행 시점 | 판정 `57e55e6` | 수정 전 `6028521` |

| 0 / 5 / 15 ms (각 3회) | **9/9 착지** (502~1,751 ms) | (측정 안 함 — 아래 구간이 이미 갈린다) |

### 2-6) 계약면 — ✅ 닫힘 (내 스캐너로 독립 확인)

내 스캐너는 채널 목록을 **두 방법**으로 뽑아 **둘이 같을 때만** 진행한다:
① `protocol.ts`의 `IPC` 객체를 `ts.transpileModule`로 옮겨 **실행해서** 읽는다,
② 주석을 지운 소스에서 `키: '값'`을 긁는다. 두 방법 모두 **216 키 · 값 전부 일치**.
(함정 하나 — 파일이 CRLF라 `//…$`의 `$`가 `\r` 앞에서 걸려 주석이 안 지워진다. 첫 판이
56개만 잡아 두 방법이 어긋났고, `\r`를 먼저 지워 고쳤다.)
구현 판정은 Rust 소스(주석 줄 제외)에서 채널 문자열이나 그 상수 이름이 **정의가 아닌
자리에서** 쓰이는가.

| 트리 | total | impl | missing |
|---|---|---|---|
| 대조군 `5d6b5a2` | 216 | 206 | **10** |
| 판정 `57e55e6` | 216 | 207 | **9** |

델타는 정확히 하나 — `app:open-directory`. 남은 9:
`talk:run` · `talk:cancel` · `talk:permission-respond` · `talk:question-respond` ·
`talk:bg-task` · `talk:event` · `app:update-check` · `app:update-install` · `app:update-event`.

**런타임 교차 확인**: 판정 exe에서 저 9개를 원시 호출 → **9/9 `{"__unimplemented":true}`**.
자리를 옮긴 `app:get-initial-dir`는 미구현이 아니다(인자 없는 기동에서 `null`을 답한다).
`src/shared/protocol.ts`는 `5d6b5a2…57e55e6` 사이에 **한 줄도 안 바뀌었다**(`git diff` 확인) —
총수 216 불변·`EngineEvent` 유니온 미접촉이 사실이다. 동결 구역(`src/main`·`src/preload`·
`src/renderer`·`out/`·`dist/`)도 미접촉.

## 3. 남은 결함

### D1 (중) — **이 라운드가 고친 배선 셋을 지키는 못이 하나도 없다** (변이로 실증)

이 라운드가 실제로 바꾼 것은 셋이다.

1. `main.rs` — `let handed = stash_from_args(); win::tray::raise_existing(handed);`
2. `tray.rs` — `let with_handoff = w.0 == RAISE_WITH_HANDOFF; … if with_handoff { deliver_pending(&a) }`
3. `app_meta.rs` — `deliver_pending`이 `pending_for_delivery(renderer_ready())`를 부른다

새로 박은 못 넷은 **순수 함수만** 만진다(`classify_with`에 클로저 주입 ·
`pending_for_delivery(false/true)` 직접 호출 · `take_pending` · 진짜 ACL).
`RAISE_WITH_HANDOFF`·`deliver_pending`·`raise_existing`·`renderer_ready`를 **이름으로라도
언급하는 테스트가 0개**다(`grep` 전수).

말로 끝내지 않고 **변이로 쟀다**. 판정 커밋의 비-git 사본(`C:\Temp\ccg-odc2-mut` ·
타깃 `D:\ccg-odcr2\tmut`)에서 한 번에 하나씩 되돌리고 `cargo test -p agentcodegui`:

| 변이 (이 라운드의 수정을 되돌린다) | 결과 |
|---|---|
| ② `if with_handoff { … }` 제거 = **인자 없는 재실행도 인계를 걷는다**(D2(b) 재개통) | **174 passed · 0 failed** |
| ① `raise_existing(handed)` → `raise_existing(true)` = 같은 병 | **174 passed · 0 failed** |
| ③ `pending_for_delivery(renderer_ready())` → `(true)` = **부팅 창의 침묵 재개통**(D2(a)) | **174 passed · 0 failed** |
| (대조) `classify_with(raw, enumerable)` → `(raw, \|_\| Ok(()))` = **D1 수정 되돌리기** | **173 passed · 1 failed** — `a_real_deny_acl_folder_is_denied` |

즉 **못 읽는 폴더 쪽(D1)은 진짜로 못이 박혔고**(그 못이 이 기계에서 실제로 도는 것도 확인:
테스트 홈과 같은 `%LOCALAPPDATA%\Temp` 아래에 같은 `icacls` 인자를 걸면 `statable=true,
listable=EPERM`), **부팅 창·납치 쪽(D2)은 배선 셋 전부가 무방비**다. 이 라운드의 커밋 제목
뒷절반(「부팅 0.8초의 폴더도 늦게나마 착지한다」)이 서 있는 자리가 정확히 그 셋이다.
누가 리팩터로 셋 중 하나를 되돌려도 174/174은 초록이고, 사용자만 폴더를 잃는다.

처방 방향(내가 고치지 않는다): 배선을 함수 하나로 내려 못을 박을 수 있게 한다 —
예를 들어 `fn should_deliver(wparam: usize) -> bool`와
`fn handoff_bit(stashed: bool) -> usize`를 두고 그 둘에 못을 박으면, 지금의 순수 함수 못들과
같은 값으로 배선이 지켜진다.

### D2 (낮음 · 이월이지만 이 라운드가 부작용을 하나 더했다) — `app:get-initial-dir`는 「한 번 쓰고 버린다」가 아니다

계약면 자신이 그렇게 적어 뒀다 — `src/shared/protocol.ts:1265`
「folder passed via "AgentCodeGUI로 열기" at launch (**consumed once**)」.
2.6.2는 실제로 그렇게 한다(`src/main/index.ts` — `pendingOpenDir`를 읽고 `null`로 지운다).
3.0은 부를 때마다 argv를 **다시 읽는다**. 실측(콜드 인자 `…\ProjB`로 기동 후 원시 호출 3회):

| | 1회 | 2회 | 3회 |
|---|---|---|---|
| 판정 `57e55e6` | `…\ProjB` | `…\ProjB` | `…\ProjB` |
| 대조군 `5d6b5a2` | `…\ProjB` | `…\ProjB` | `…\ProjB` |

대조군도 같으니 **이월**이다. 다만 이 라운드가 그 자리에 **부작용을 하나 더했다**:
못 여는 콜드 인자로 기동해 카드를 닫은 뒤 조회를 다시 하면 **카드가 되돌아온다**(실측 —
`cardAfterReQuery`에 같은 문구가 다시 앉는다). 대조군은 애초에 카드가 없어 이 모양이 없었다.

도달 경로: `src-tauri/src/crash.rs`의 `reload_all()` — 렌더러가 죽으면 복구가 **모든 창의
문서를 다시 세운다**. 그러면 `App`이 다시 마운트되어 `getInitialDirectory()`를 또 부르고,
기동 때 준 폴더가 **다시** 적용된다(사용자가 그 사이에 다른 폴더로 옮겨 놨더라도).
대화가 있으면 「폴더를 바꿀까요」 카드가 난데없이 뜨고, 턴이 도는 중이면 조용히 버려진다.

### D3 (낮음) — 경로를 **다듬지 않는다**(2.6.2는 `path.resolve`)

`classify()`의 주석은 이 자리를 「2.6.2 `openedDirFromArgv`의 `path.resolve(a)` 자리」라고
적었지만, `path.resolve`는 **정규화도 한다**(끝 구분자 제거 · `.`/`..` 접기 · `/`→`\`).
3.0은 절대 경로면 그대로 돌려준다. 원시 호출 실측:

| 인자 | 3.0 `dir` | 2.6.2 `path.resolve` |
|---|---|---|
| `C:\…\ProjA\` | `C:\…\ProjA\` (끝 역슬래시 그대로) | `C:\…\ProjA` |
| `C:\…\ProjA\..\ProjB` | `C:\…\ProjA\..\ProjB` | `C:\…\ProjB` |
| `C:\…\ProjA\.\` | `C:\…\ProjA\.\` | `C:\…\ProjA` |
| `C:/Temp/…/ProjA` | `C:/Temp/…/ProjA` (슬래시 그대로) | `C:\Temp\…\ProjA` |

화면 실측: 이미 `…\ProjA`를 연 상태에서 `…\ProjA\`를 열면 chat-head가 **끝 역슬래시가 붙은
쪽으로 바뀐다**. 대화를 날리지는 않는다 — `sameCwd`(`app/src/lib/btw.ts`)가 구분자와 끝
슬래시를 정규화해 「같은 폴더」로 보기 때문이다. 그러나 `.`/`..`는 `sameCwd`도 못 접으므로
그 모양이 오면 「다른 폴더」로 취급되어 대화 리셋 확인 카드까지 간다.
탐색기 `%V`는 정규 경로를 주므로 출하 경로에서 밟기는 어렵다(드라이브 루트가 `C:\`인 것은
정규형이라 문제없다 — 실측 `{"ok":true,"dir":"C:\\"}`). 콜드 쪽은 이월, **웜 쪽은 이 라운드가
새로 만든 통로**라 이월이 아니다.

### D4 (낮음) — 인자가 둘 이상일 때 **3.0은 앞의 것, 2.6.2는 뒤의 것**

2.6.2 `openedDirFromArgv`는 `for (let i = argv.length - 1; i >= 1; i--)` — **마지막** 폴더가
이긴다. 3.0은 `parity::misc::initial_dir`도 `pick_candidate`도 **처음** 폴더가 이긴다
(단위 테스트 `candidate_matches_the_cold_rule_and_keeps_the_bad_one`이 그렇게 못을 박아 뒀다).
실측(`exe <ProjA> <ProjB>`): 콜드 `…\ProjA` · 웜 `…\ProjA` — **둘이 서로 같은 것은 맞다**
(이 라운드의 목표였다). 다만 장부 §6.11 표의 「콜드 런치 … **같다**(`parity::misc::initial_dir`)」는
2.6.2와 같다는 뜻으로 읽히고, 이 축에서는 사실이 아니다. 탐색기는 인자를 하나만 주므로
출하 경로에서는 안 밟는다.

### D5 (낮음 · 정보) — 인계 파일을 **못 쓰면** 폴더는 다시 조용히 사라진다

창은 앞으로 오고 **cwd 불변 · 카드 0 · 페이지 이벤트 0** — N3의 원래 모양 그대로다.
트리거가 인위적이라(같은 이름의 디렉터리 · 디스크 가득 · 권한) 등급은 낮지만,
「폴더는 이제 조용히 사라지지 않는다」에는 이 구멍이 남아 있다.

### D6 (낮음 · 정보) — 겹친 두 번은 **끝 상태가 정해져 있지 않다**

`6028521`·`57e55e6`과 장부 §6.11.4는 「끝 상태는 같은 B」라고 적었다. 내 실측 4쌍 중

않는다. 다만 「끝 상태는 같은 B」는 결정적 사실이 아니라 **확률이 높은 쪽**이다.

### D7 (낮음 · 이월 · 2.6.2와 글자 그대로 같음) — 턴이 도는 중이면 폴더는 아직 조용히 버려진다

## 5. 판정

**불합격(pass=false).**

확인 크리틱 R1이 실패시킨 다섯 칸은 **내 손에서도 진짜로 닫혔다.** 대조군이 0/3인 자리에서
판정 exe는 3/3이고, 수정 전 exe가 7/20인 부팅 경주에서 판정 exe는 29/29다. 못 읽는 폴더는
웜·콜드·원시 호출 세 자리 모두에서 「안을 읽을 권한이 없어요」라고 말하고 열리지 않으며,
빈 폴더는 그대로 열린다. 계약면도 10→9로 내 독립 스캐너와 런타임 원시 호출 양쪽에서 맞다.

그런데 **그 닫힘을 지키는 못이 없다.** 이 라운드가 실제로 고친 배선은 셋인데
(`raise_existing(handed)` · `if with_handoff` · `pending_for_delivery(renderer_ready())`),
셋을 하나씩 되돌린 변이 세 벌이 **전부 174/174 초록**이다. 같은 잣대로 D1 수정을 되돌리면
못 하나가 즉시 붉어지므로, 이건 「테스트로 못 잡는 종류」가 아니라 **이 라운드가 안 박은
것**이다. 커밋 제목의 뒷절반이 서 있는 자리가 정확히 그 셋이다.

그리고 장부 §6.11.4 — R1의 「남은 비대칭 하나」가 사실이 아니라고 고쳐 적은 그 문단이,
**다시 「지금 남은 것은 하나다」**라고 적혀 있다. 내가 잰 것만으로도 넷이다(겹친 두 번 +
