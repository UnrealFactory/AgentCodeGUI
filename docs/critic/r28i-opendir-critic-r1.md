## 3. 남은 결함

### D1 (중) — 권한 없는 폴더를 **열고**, 탐색기가 "비어 있음"이라고 **거짓말한다**

`classify()`가 `std::fs::metadata` 한 번으로 판정하는데, Windows에서는 부모를 읽을 수만
있으면 **deny ACL이 걸린 폴더에도 `metadata`가 성공한다**(디렉터리 엔트리의 속성 폴백).
그래서 `Verdict::Denied`는 사실상 도달 불가고, 대신 `Ok`로 떨어져 **그 폴더가 작업 폴더가
된다.** 화면은 사유를 말하지 않고, 파일 트리는 `비어 있음`이라고 적는다 — 사용자는 "빈
폴더구나"라고 읽는다.

재현:
```
icacls C:\Temp\x\Denied /inheritance:r /grant:r SYSTEM:(OI)(CI)F
CCG_HOME=<격리> agentcodegui.exe        # 첫 인스턴스
CCG_HOME=<격리> agentcodegui.exe C:\Temp\x\Denied
```
실측: 카드 0장 · chat-head가 `…\Denied`로 전환 · `.fxtree` 텍스트 = `비어 있음`(행 0) ·
원시 호출 `{"ok":true,"dir":"C:\\Temp\\odcrit\\fixtures\\Denied"}`.
같은 폴더에 Node `fs.readdirSync`는 `EPERM`을 던진다(= 2.6.2 `statSync().isDirectory()`
경로였다면 이 인자는 애초에 버려졌다).
대조군은 웜 경로에서 아무 일도 안 하므로 **이 착지는 이 라운드가 새로 만든 것**이다
(콜드 경로의 같은 증상은 대조군에도 있다 — 그쪽은 이월).
커밋 제목 「못 여는 경로는 화면이 말한다」가 정확히 "못 여는"이 문자 그대로인 칸에서 거짓이다.

처방 방향(내가 고치지 않는다): `Ok(dir)` 직전에 `read_dir(&abs).next()` 한 번을 더 보거나
(같은 블로킹 스레드 안이라 비용 위치는 그대로), 최소한 `Verdict::Denied`를 살릴 수 있는
잣대로 바꾼다. 지금의 단위 테스트 `dir_wins_and_file_is_named`는 `Denied`를 **문자열
이름표로만** 확인해서 이 칸을 못 잡는다.

### D2 (중) — 부팅 중에 온 폴더는 조용히 사라지고, 그 **잔해가 다음 재실행을 납치한다**

지연 스윕(데운 격리 홈 · 매 회 새 프로세스):

| 두 번째 실행 시점 | 착지 | 카드 | 인계 파일 |
|---|---|---|---|
| +30 ms | **안 함** | 없음 | **남는다**(리스너가 아직 안 붙어 브로드캐스트가 통째로 유실) |
| +327 ms | **안 함** | 없음 | 소비됨(리스너는 받았지만 렌더러 `listen()` 전이라 방출이 버려짐) |
| +825 ms | 함 | — | 없음 |
| +1.5 / 2.5 / 4 / 6 s | 함 | — | 없음 |

즉 **기동 후 대략 0.3~0.8초 창**에서 N3의 원래 증상(폴더가 오류도 안내도 없이 사라짐)이
그대로 남아 있다. 첫 실행이 처음(이관·엔진 게이트·패치노트)이면 창은 더 길다 — 신선한
홈에서 +400ms에 쏜 인계는 착지하지 못했다.

여기서 끝이 아니다. `+30ms` 줄의 **남은 인계**가 15초 TTL 안에 살아 있으면, 이어지는
**인자 없는** 재실행이 그것을 소비한다:

```
exe <B>                      # 첫 인스턴스 기동
(20ms 뒤) exe <A>            # 경주 — A는 사라진다, 인계 파일은 남는다
… 창을 X로 숨김 …
exe                          # 인자 **없음** — 규약상 raise만
→ 창이 서고 cwd가 A로 바뀐다   (실측 hijacked=true)
```
「인자 없는 두 번째 실행이 그냥 raise만 하는가」는 이 라운드가 지켜야 한다고 적힌 무회귀
항목이고, 대조군에는 인계 파일이라는 물건 자체가 없어 이 납치가 **불가능**하다 —
따라서 이건 이월이 아니라 **새 거동**이다.

처방 방향: 브로드캐스트를 받을 리스너가 설 때까지 인계를 살려 두고(창이 서면 한 번 더
소비 시도), 방출은 렌더러가 구독을 마친 뒤로 미룬다(또는 §6.11이 말한 조회 채널).
지금은 `deliver_pending`이 **한 번**만, 그것도 raise 신호에만 걸려 있다.

### D3 (중 · 이월) — 콜드 런치의 나쁜 인자는 여전히 조용하다

`coldBad`: 파일 → 카드 0 · 없는 경로 → 카드 0 (판정·대조군 **동일**, 2.6.2와도 동일).
빌더가 범위 밖이라고 명시했고 나도 그 판단 자체는 반박하지 않는다. 다만 장부 §6.11이
이것을 **「남은 비대칭 하나」**로 적은 것은 D1·D2를 빼먹은 셈이라 사실과 다르다(2-7).

### D4 (낮음) — 공백만 있는 인자는 카드도 없이 사라진다

`take_pending()`이 `trim()` 후 빈 문자열을 `None`으로 떨어뜨려, 웜 인계 경로에서
`Verdict::Empty`는 **도달 불가**다(원시 호출로만 뜬다 — 실측 `{"ok":false,"reason":"empty"}`).
재현: `exe "   "` → 카드 0 · cwd 불변 · 아무 표시 없음. 탐색기 `%V`는 공백을 주지 않으므로
출하 경로에서는 안 밟지만, "사유를 말하려고 첫 비-스위치 인자를 들고 온다"는
`pick_candidate`의 설계 의도가 바로 이 칸에서 무효가 된다.

### D5 (낮음 · 정보) — 겹친 두 번의 「…으로 열기」에서 앞의 것은 사라진다

`exe A` 직후 `exe B` → 인계 파일이 덮여 A는 소비되지 않는다(실측: 착지 = B).
2.6.2(Electron `second-instance`)는 둘 다 순서대로 적용하지만 **끝 상태는 같은 B**라
사용자가 보는 결과는 같다. 기록만 남긴다.
