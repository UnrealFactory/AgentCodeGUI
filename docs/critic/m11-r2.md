# M11 R2 확인 크리틱 — 토큰 안전 (`9cd449c`)

**임무**: R2가 닫았다고 적은 자리(C1 치명 · C2 · C3 · native-tls)를 독립 재실행으로 판정한다.
빌더가 낸 산출 JSON은 증거로 쓰지 않았다 — 게이트를 내가 다시 돌려 나온 값, 내가 새로 짠
공격 재생, 내가 심은 뮤테이션만 적는다. **재로그인을 유발했던 자리**라 예산은 코드 대조와
토큰 경로에 몰았고 네트워크는 2건만 썼다.

R1 도구 A3의 실측 흔적이 R2의 방어를 그대로 보여 준다 — 훅은 예약을 모르니 두 채팅에게
같은 1등을 내줬고, 엔진 장부가 그중 하나를 **거절하고 되물었다**:

```text
[A3] chat-1=b@x chat-2=c@x picks=[("chat-1","b@x"), ("chat-2","b@x"), ("chat-2","c@x")]
```

### 2.1 예산 문 — 실 창에서 센 숫자

빌더가 못 박은 두 값 외에 **하나를 더** 쟀다. PoC의 `toggle` 시나리오는 실 창에서 설정
스위치를 **손으로 켠다**. 그 직후 셸의 계수기가 이렇다:

```json
"after": { "on": true, "busy": [], "worker": { "runs": 0, "fetches": 0 }, "picked": null }
```

즉 **토글을 켜는 것만으로는 워커가 안 돈다**(R1은 부팅만으로 전 계정을 물었다). 조회의
계기가 `Switcher::ask` 하나라는 주장이 실 창에서 참이다.

| 시나리오 | on | worker |
|---|---|---|
| `off` | false | `runs=0 fetches=0` |
| `toggle`(막 켬) | true | `runs=0 fetches=0` |
| `pick`·`none`·`dirty`·`chain`(한도 장전 뒤) | true | `runs=1 fetches=0` |

`fetches=0`은 PoC가 `usage-cache.json`을 신선하게 심어 두기 때문이다(캐시 문 ③).

## 4. C1 재감사 — `net.rs` 호출 그래프 전수

도구: `docs/critic/tools/critic-m11r2-token.rs`(격리 홈 · `CCG_NO_NET=1` · 실 HTTP 0).

### 4.1 그래프

```text
[워커 스레드 ccg-acct-switch]  (제품 유일 진입점)
  acct_switch::collect → fetch(email)
   └ net::fetch_account_usage(email)
      ├ net::access_token(email)
      │   ① claude::account_access_token  → Some ⇒ 회전 없음(2.6.2 의미론)  ✔
      │   ② lane(email).lock()            → 계정별 단일 비행                ✔
      │   ③ 이중 검사(앞 주자 결과 재확인)                                  ✔
      │   └ rotate(email)
      │       ├ refresh_token / freshest_creds(base 스냅샷)   ← ★ 네트워크 **전에** 뜬다
      │       ├ for req in usage::refresh_requests → send()   ← 서버 회전(되돌릴 수 없음)
      │       └ 2xx ⇒ store_rotation(base, body, sent_refresh)
      │             ├ access_token 없음 ⇒ **BadBody로 즉시 이탈**  ← F3(회전 결과 유실)
      │             ├ apply_refresh None ⇒ 실패로 셈             ✔
      │             ├ persist_refreshed ×3(40ms)                ✔
      │             └ 실패 && rotated ⇒ TokenLost + eprintln     ✔
      └ usage GET (+429 1회 재시도)
  └ TokenLost ⇒ 로그 한 줄 + None  ← F2(격리·복구 없음)
```

진입점은 둘뿐이다(`acct_switch::fetch`, 진단용 `ccg_auth_probe`). `net::liveness`는 호출자가
없다(사문). 회전이 나는 경로는 `access_token → rotate` **하나**이고, 그 하나는 레인 안에 있다.

### 4.2 결과 (5 red · 1 green)

| # | 과녁 | 결과 |
|---|---|---|
| T1 | 200 + 새 refresh인데 `access_token`이 없다 | **red** — `BadBody`로 이탈, 새 토큰 저장 안 됨, `TokenLost`도 아님 |
| T2 | `TokenLost`가 오경보인가 | **red** — 폴더엔 `r-2`가 멀쩡히 앉았는데 판정은 "재로그인" |
| T3 | 레인당 교환 1건인가 | **red** — 동시 4호출 → **4건 전부** 교환 시도 |
| T4 | 다른 프로세스와 동시에 | **red** — 아래 §5 |
| T5 | `TokenLost` 뒤 그 계정이 후보에서 빠지나 | **red** — `pick=lost@x`(**1등**) |
| — | R1 도구(`critic-m11-token`) | green — 제품 경로는 **여전히 회전한다**(설계상 유지) |

**T3의 뜻**: 레인은 *직렬화*지 2.6.2의 `refreshInflight`(약속 공유)가 아니다. 앞 주자가
성공하면 뒤 주자는 이중 검사에서 걸러진다 — 그래서 **성공 경로의 이중 회전은 정말 없다**.
그러나 앞 주자가 실패하면(4xx·전송 실패) 뒤 주자는 자기 교환을 새로 나간다. 오늘은 호출자가
워커 스레드 하나라 무해하고, 커밋의 *"구조적으로 없다"* 는 **성공 경로에 한해** 참이다.

## 5. ★ 새 공격 — 다른 프로세스가 같은 계정을 쓸 때 (F1)

`persist_refreshed`는 계정 폴더를 원자 저장한 **뒤** `accounts.json`을 **통째로 읽고-고쳐-쓴다**
(`write_store_file` — 잠금 없음 · mtime 검사 없음 · 반환값 없음). 같은 홈을 쓰는 다른
프로세스가 그 사이에 자기 쓰기를 끝내면 **한쪽 갱신이 사라진다.**

재현(T4): 격리 홈 하나 · 프로세스 둘(부모=테스트, 자식=같은 바이너리) · 실 네트워크 0.
부모는 `mine@x`를, 자식은 `yours@x`를 120회씩 회전시키고, 자식은 그 사이 다른 앱처럼
`ghost@x`를 **로그인/로그아웃**한다.

```text
[T4-child] 내 회전 120회 중 백업에서 지워진 건수=1
[T4-child] ★ 로그아웃한 ghost@x가 되살아난 횟수=11
[T4] 부모 120회 회전 중 백업에서 지워진 건수=1   (다른 주행: 4·5·6)
[T4] freshest(mine)=Some("m-119")      ← 폴더 사본이 살아남아 토큰 자체는 무사
```

- **토큰은 대체로 살아남는다.** 폴더 `.credentials.json`은 계정마다 따로이고
  `freshest_creds`가 `expiresAt`이 큰 쪽(=폴더)을 고른다. 그게 지금의 유일한 완충이다.
  대신 백업(credEnc)에는 **죽은 refresh 토큰**이 남는다 — 폴더가 지워지는 날
  (`delete_account_dir` · 재설치 · 프로필 이전)이 곧 재로그인이다.
- **계정 목록은 사본이 없다.** 로그아웃·로그인·순서·기본 계정은 `accounts.json`에만 산다.
  그래서 잃어버린 갱신이 **로그아웃 취소**로 나타난다 — 실측 9.2%(11/120).
  되살아난 항목은 `credEnc`를 그대로 물고 있으므로 **살아 있는 토큰째** 돌아온다.
- **왜 지금 새로운가**: 3.0의 계정 IPC는 아직 **읽기 전용**이다(`ipc/mod.rs:186 "accounts (읽기 전용)"`).
  M11 R2 이전에는 3.0이 `accounts.json`을 **쓰는 경로가 없었다**. 자동 전환 워커가 그
  성질을 처음 만들었고, 그 쓰기는 사용자 조작과 무관한 배경 스레드에서 난다.
  짝은 이미 존재한다 — 같은 홈(`~/.agentcodegui`)을 쓰는 2.6.2 실앱은 로그인·로그아웃·
  토큰 리프레시·`syncAccountTokens`로 같은 파일을 쓴다.
- 3.0이 나중에 로그아웃을 이식하면 같은 레이스가 **프로세스 안**으로 들어온다(워커 스레드 vs 허브).

수선 방향(제품 코드는 안 고쳤다 — 제안만): `accounts.json`에 **파일 잠금**을 두거나,
`persist_refreshed`가 자기 계정 항목만 **병합**하도록 좁히거나(읽기 직후 mtime 재확인 +
불일치면 재시도), 최소한 `write_store_file`의 실패를 **반환**한다(지금은 `let _`이라
백업 쓰기 실패가 `Ok(())`로 나간다 — C1이 닫은 바로 그 침묵의 마지막 잔재다).

## 6. native-tls — 검증까지 선다

도구: `docs/critic/tools/critic-m11r2-tls.rs`. R1은 405(=핸드셰이크 성립)까지만 봤다.
성립은 검증의 증거가 아니라서(검증을 끈 커넥터도 405를 받는다) **틀린 인증서**를 붙여 봤다.

```text
[TLS+] status=405 elapsed=244ms bodyLen=132
[TLS-] 거절됨(정상)=transport: https://wrong.host.badssl.com/: Connection Failed:
       native_tls connect failed: 인증서의 CN 이름이 전달된 값과 일치하지 않습니다.
       (os error -2146762481)   elapsed=1524ms
```

`-2146762481` = `CERT_E_CN_NO_MATCH`. schannel이 체인 + 호스트 이름을 **실제로** 검증한다.

### 사설 루트 · 프록시 환경

| 가정 | 판정 |
|---|---|
| 사내 MITM 프록시(윈도 루트 저장소에 사내 CA가 배포됨) | **이제 통과한다.** rustls+번들 루트는 거절했다 — 그 환경 사용자에겐 기능이고, 신뢰 기반이 OS로 넘어간 것은 사실이다. Cargo.toml에 그 대가가 적혀 있다(코드가 문서와 일치) |
| **명시 프록시**(`HTTPS_PROXY`·`ALL_PROXY`) | **안 통한다.** `ureq`의 프록시 자동 감지는 `proxy-from-env` 피처인데 `default-features = false, features = ["native-tls"]`라 꺼져 있고, `AgentBuilder::proxy()`도 안 부른다. 사내 강제 프록시 환경에서는 usage 조회·**토큰 회전이 전부 `Transport` 실패**다. rustls 시절과 같으므로 **native-tls의 회귀는 아니다**(선행 결함) |
| 리다이렉트 유출 | `redirects(0)` — 남의 호스트로 `Authorization`이 새지 않는다 ✔ |

## 7. C2 · C3 독립 재생

도구: `docs/critic/tools/critic-m11r2-attack.rs`. 훅은 **전부 예약을 모르는 스텁**이다
(구형·미배선 훅과 같은 모양) — 마지막 문을 닫는 것이 엔진 장부라는 주장을 그 조건에서만
확인할 수 있기 때문이다. **4판 전부 green.**

| # | 과녁 | 실측 |
|---|---|---|
| B1 | 채팅 **셋**이 한 tick에 동시에 열린다 | `착지=["b@x","c@x","d@x"]` — 셋 다 다르다. 훅질문 6회(장부가 3번 되물었다) |
| B2 | 자유 계정 1 · 대기 채팅 3 | `착지=["b@x","a@x","a@x"]` — 하나만 옮기고 둘은 표를 든 채 남는다 |
| B3 | 표를 죽이는 **네 경로** | ①손수 계정 변경 ②`HoldCancel` ③전환 성사 = 대기문장 0 · ④훅이 굳음 = **1**(늦게라도 말한다) |
| B4 | 예약이 영구 잠금인가 | `TAKEN_TTL_MS=60000` 뒤에는 남에게 다시 열린다 |

B3-④가 이 판의 양성 대조다: "안 나온다"만 재면 문장을 통째로 지운 구현도 green이 된다.

## 8. 남은 격차

| # | 급 | 무엇 |
|---|---|---|
| **F1** | **중대** | §5 — `accounts.json` 통짜 쓰기에 잠금이 없다. 다른 프로세스와 겹치면 백업이 죽은 토큰으로 남고(≈1~6/120), **로그아웃이 취소된다(11/120)**. `write_store_file`은 실패를 삼킨다(`let _`) |
| **F2** | **중대** | `TokenLost`·조회 실패 계정에 **격리도 백오프도 없다.** ⑴ 오염가드는 파일만 보므로 죽은 refresh도 `NeedsRefresh`(통과) ⑵ 캐시에 지난 usage가 있으면 그 계정이 **다음 전환의 1등**으로 나간다(T5 실측) → 갈아탄 자리에서 로그인 창 ⑶ 캐시에 값이 없으면 `usage_unknown`이라 `pick`이 **매 tick** 다시 묻고, 워커 쿨다운 20초마다 **죽은 토큰으로 교환 POST**가 반복된다(상한 없음) |
| **F3** | 경 | T1 — 200 응답에 `access_token`이 없으면 `store_rotation`이 **맨 첫 줄에서** 이탈한다. 그 응답이 새 refresh를 물고 있었다면 회전 결과는 저장도 `TokenLost`도 없이 사라진다. 실서버에서 드문 모양이지만, C1이 닫으려던 **바로 그 침묵**의 잔재다 |
| **F4** | 경 | R1 C1-④가 **안 닫혔다.** `collect()`의 `busy`는 루프 **진입 전 한 번**만 읽는다(`acct_switch.rs:319`). 계정 6개 × (교환 2 + 조회 1) × `USAGE_GAP_MS=1200` ≈ **최대 20초**. 그 사이 턴을 시작한 계정도 조회·회전 대상이라 **살아 있는 CLI 밑에서 그랜트를 돌린다**(CLI의 사본과 이중 회전) |
| **F5** | 경 | **헤드라인 자물쇠가 flaky.** `booting_with_the_toggle_on_queries_nothing`이 내 1차 `--workspace` 주행에서 red였고(그 바이너리에서 게이트가 멈췄다), 격리 재현에서 **1/15**. 원인: `CCG_HOME`은 프로세스 전역인데 같은 바이너리의 `engine::codex_versions::tests`가 `acct_switch::tests`의 직렬화 뮤텍스를 **안 잡고** set/remove 한다. 그 `remove_var` 창에서는 `app_home()`이 **사용자 실홈**으로 떨어지고, 그 순간 `home()`의 `write_ui_prefs`·`seed()`의 `write_store_file`이 실홈을 쓴다(구조적 도달 가능 — 이번 주행에서는 미관측: 실홈을 임시 경로로 돌려 15판 돌렸을 때 그 폴더에 아무것도 안 생겼다) |
| **F6** | 경 | T3 — 레인이 실패를 안 합친다(4호출 → 4교환). 오늘 무해하지만 커밋 문구는 성공 경로에서만 참 |
| **F7** | 정보 | T2 — `TokenLost` 오경보. 폴더 저장은 이미 성공했는데 로그는 "재로그인이 필요할 수 있습니다"라고 말한다(방향은 안전) |
| **F8** | 정보 | 예약 TTL 불일치(셸 `RESERVE_TTL=30s` vs 엔진 `TAKEN_TTL_MS=60s`)와, **거절된 후보도 셸에서는 예약된다**(`Switcher::pick`이 반환 전에 `reserve`). 재질문 루프 한 바퀴마다 계정 하나가 30초 동안 남에게 가려진다 — 전환을 최대 30초 늦출 수 있다 |
| **F9** | 정보 | 명시 프록시 미지원(§6). native-tls 회귀는 아니고 선행 결함 |

### 다음 라운드 순서 (내 권고)
