# 파일 뷰어 독립 창 R1 — 뷰어를 잡아 옮기고, 다음 파일도 그 자리에

> 사용자 요구(2026-09-02): *"파일 클릭해서 띄우는 뷰어 위치를 상단바를 잡아 옮길 수 있고,
> 다음 파일을 열 때도 거기 위치가 기억되면 좋겠다 — 듀얼 모니터에서 한쪽은 GUI, 한쪽은 파일."*
> 방식 결정: **독립 OS 창** (사용자: "독립 OS로 해야 할 것 같은데, 대신 성능·부드러움을
> 위해서 지금까지 작업했으니 이것도 그렇게 되면 좋겠어").

## 1. 왜 창인가

카드 뷰어(`FileModal`)는 메인 창 **안**의 오버레이(`.fv-overlay` absolute inset:0)라 창 밖으로
못 나간다. 다른 모니터에 두려면 OS 창이어야 한다 — 추가 채팅 창·패널 팝아웃 창과 같은 결론,
같은 껍데기(`shared_env`·프레임리스·아크릴). 창 안 드래그만 넣는 안(B)은 공사가 작지만
듀얼 모니터 목적을 못 채워서 제시만 하고 택하지 않았다.

## 2. 설계 — "창은 자리, 파일은 페이로드"

| 자리 | 파일 | 역할 |
|---|---|---|
| 셸 | `src-tauri/src/viewer.rs` | 창 하나(`viewer`) 생성·표시·숨김·자리 저장, 끈적한 모드, 되돌아갈 주소(ORIGIN) |
| 저장 | `crates/ccg-store/src/viewer_state.rs` | `viewer-window.json` = `{window, x, y, width, height, maximized}` |
| 채널 | `ipc/windows.rs` `VIEWER_*` · `protocol.ts` `IPC.viewer*` | 호출 8 + 이벤트 3 |
| 렌더러 | `app/src/components/ViewerWindow.tsx` (`#viewer`) | `FileModal windowed` 하나가 창 전체 |
| 호스트 | `lib/viewerWindow.ts` + App·SessionWindow·MultiAgent·PanelWindow | 파일 열기를 모드에 따라 창/카드로 가른다 |

- **끈적한 모드.** 카드 헤더의 「별도 창으로」를 한 번 누르면 `window=true`가 서고, 이후
  모든 파일 열기(탐색기·툴 로그·변경 파일·Git 카드·패널·추가 채팅 창)가 그 창으로 간다.
  창 헤더의 「창 안으로」만이 모드를 끈다. X·Esc·Ctrl+W·Alt+F4는 **파일 닫기**다.
- **숨김 재사용.** 파일을 닫으면 창을 부수지 않고 숨긴다. 다음 파일은 창 생성 없이 같은
  자리에 뜬다. 자리는 Moved/Resized 400ms 디바운스로 저장, 창을 만들 때 `on_screen`
  (모니터 탈착) 검사 뒤 복원. 모니터가 빠졌으면 부른 창에서 60px 어긋나게.
- **빈 창 번쩍임 방지.** 창은 숨긴 채 만들고(또 숨긴 채 내용을 바꾸고) 렌더러가 파일을
  그린 뒤(`FileModal onReady` → `viewer:shown`) `show()`. 안전망 타이머(콜드 1.5s·웜 0.6s)는
  렌더러가 침묵할 때만 — 하네스가 그 횟수(`fallbackShows`)를 읽는다(정상 = 0).
- **드래그는 OS 것.** `.fv-win .diff-head{-webkit-app-region:drag}` → `chrome.ts`가
  `startDragging`으로 넘긴다. Aero Snap·더블클릭 최대화 그대로.
- **되돌아갈 주소.** 마지막으로 파일을 보낸 창(ORIGIN)이 질문 패널 전송(`viewer:ask-selection`)과
  「창 안으로」(`viewer:docked`)를 받는다. 멀티 그리드의 패널 파일도 메인 창의 App이 페이로드째
  받아 카드로 그린다(cwd·diff가 실려 오므로 패널 자리와 무관).
- **페이로드는 그 파일 하나에 필요한 것만.** 세션 전체 `diffs` 대신 `diffs[path]` 하나,
  Git 스냅샷 오버라이드, 질문 가능 여부(`askable`).
- **마우스 제스처 →↑(RU).** 멀티 패널의 "최대화 문법"과 같은 획. 카드에선 **곧장 「별도 창으로」**
  (사용자 결정 2026-09-02 — 카드 최대화를 거치지 않는다), 독립 창에선 OS 최대화/복원.
  ↓→(DR)은 두 곳 다 닫기(창에선 파일 닫기 = 숨김).

## 3. 실측 — `scripts/poc-viewer-window.mjs` (릴리즈 exe · 격리 홈 · 가짜 CLI)

`docs/critic/viewer-window-r1.json`. 3회 반복 모두 22/22 PASS.

| 항목 | 값 |
|---|---|
| 「별도 창으로」 클릭 → 창 표시(파일 그려진 뒤) | **474 ms** (콜드 — 창 생성 + 청크 + 파일 읽기) |
| 파일 닫기(숨김) → 다른 파일 클릭 → 같은 자리에 표시 | **42 ms** (웜) |
| 재시작 뒤 첫 파일 클릭 → 저장된 자리에 표시 | **470 ms** |
| 카드에서 →↑ 제스처 → 창 표시(숨김 창 재사용) | **37 ms** |
| 안전망 타이머로 보인 횟수 | 0 (전부 렌더러 신호 경로) |
| Win32로 옮긴 자리 → `viewer-window.json` | 좌표 일치(±2px) · 재시작 뒤 그 자리 |

메모리(프로세스 트리, 1.5s 정착, **언어 서버 node.exe 제외** — 코드 파일을 열면 LSP가 뜨는데
그건 카드도 똑같이 치른다):

| 상태 | vs 기준 | WS | Private |
|---|---|---|---|
| 카드로 main.ts 열기 | 빈 앱 | +55 MB | +23 MB |
| 창으로 같은 파일 | 카드 열림 | **+71 MB** | **+37 MB** |
| 파일 닫고 창 숨김(웜 유지) | 카드 닫힘 | **+53 MB** | **+21 MB** |

렌더러 프로세스는 **하나뿐**이다(`--process-per-site` 공유) — 창이 더 생겨도 브라우저·GPU
프로세스가 복제되지 않았다(트리에 renderer 1개). 창 하나의 값은 그 문서의 DOM/힙과 합성 표면이다.

## 4. 알려진 교환·후속

- 숨긴 창을 **영구 유지**한다(웜 42ms의 대가 ≈ Private +21 MB). 유휴 메모리를 더 아끼려면
  "N분 숨김 뒤 파기"를 넣을 수 있다 — 사용자 결정 대기.
- 크래시 복구(`recreate_windows`)는 뷰어 창을 되세우지 않는다 — 다음 클릭이 곧 복구, 자리는 디스크에.
- 뷰어 창의 `ui-prefs` 저장(줌 등)은 다른 창들과 같은 통(blob) 경합 성질을 가진다(기존 규약).
- 이 문서의 수치는 1.5s 정착이라 60s 유휴 게이트 수치와 직접 비교하지 않는다.
